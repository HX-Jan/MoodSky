# W4 H02 记录与回顾缺陷修复

## H02-01 缓存记录控制器跨账号保留草稿

触发：账号A在Today选择CUSTOM并留下草稿；离开页面，在其他入口退出并登录B，再回Today。原控制器不订阅账号绑定变化；页面只判断当前是否游客，若换号后已登录且旧草稿为dirty，refreshIfClean会保留旧草稿。记录编辑器内存及正在等待的旧保存响应存在同一缺口。

修复前：新增4项中Today、record以及迟到保存的3项失败，旧内容或loaded状态仍保留；同账号重试用例通过。这是本地可复现的代码缺陷，不是声称发现了真实用户数据事件。

修复：记录控制器接收sessionState，Today与record都传入正式绑定。已建立绑定退出或被替换时，清空记录、正文、CUSTOM名、标签、确认和未确认请求，并推进响应代次，使旧保存不能回填或通知“已保存”。A→B→A仍视为新绑定。首次null→A认证可在读操作中完成；相同绑定和演示模式不误清空。dispose移除订阅。

同账号网络失败仍使用原requestId和payload重试；换号撤销的是旧账号内存操作，不自动重放到新账号，也不假设服务器撤销了已发出的旧写入。该旧账号的结果应在本人再次登录后重新读取确认。
