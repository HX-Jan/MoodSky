# 校园手动打卡

11月4日负责人再次明确：用户自行前往推荐地点，点击完成即可打卡，不获取或核查位置，也不以地点核验材料作为基本流程的前置条件。本次从main `f6af9094d6b9f712926d771340367134c5ea3386`实现源码，跟踪[校园需求 #102](https://github.com/HX-Jan/MoodSky/issues/102)。不改写成员原报告、核验结论或个人验收。

## 页面方案

沿用现有中文界面：纸色#faf8f3、白色#ffffff、正文#25333a、次级文字#56656d、主按钮#386e61、浅绿#eaf1ea。使用平台中文无衬线字体；标题、地点名、说明分三级，全部左对齐。页面顺序为校园标题、一次简短提示、五个地点和各自完成按钮。保留四个主标签、天气图标及右上角原生分享；首页导航仍为MoodSky。

复核：不给每项再加重复“推荐”标签、装饰图标、进度口号或定位核验说明。简短文字方位直接展示，不要求用户先打开详情或补材料；按钮保持至少44px高、细边框和已有轻微按压反馈。模拟校园天气仍保留明确的示意标识。

## 接口与私人数据

- `campus.checkins`：私有读取，无payload字段，返回服务器北京时间日期和当天本人完成项。
- `campus.checkIn`：私有写入，payload只有`placeId`，复用原requestId重试。服务端从可信账号取归属和时间，使用推荐清单中的稳定编号，无定位或到场核验。
- 同账号、同地点、同北京时间日期只保留一条；原请求跨午夜重试返回原日期。未确认结果不显示完成；切号清空旧状态，旧响应不能覆盖新账号。游客可浏览，点击打卡进入微信登录，返回后由用户再次点击。
- 新增`place_checkins`私人集合（源码方案，尚未部署），确定性文档ID；参与账号事务围栏、活动域`tasks`来源修订及导出失效。与普通任务历史分开，完整JSON/Markdown导出包含打卡，注销清理删除本人记录和回执，保留公共地点。
- 新集合默认客户端拒绝读写，访问只经云函数。新增集合/索引是部署计划，不代表已配置云端；现有服务不支持时显示未开放，不能伪造成功或自动切换本地演示。

首批五个地点名称及文字方位来自Qinghan [11月4日提交](../qinghan-zhang/place-catalogue-20261104.json)。本功能使用推荐资料，不将原`pending_review`提升为已核验，不发布营业、无障碍或到场保证。历史已核验目录继续保留在体验预览及原回归中，不再作为普通用户基本打卡的门槛。
