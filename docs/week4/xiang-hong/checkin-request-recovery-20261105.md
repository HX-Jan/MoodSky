# H04 打卡原请求跨重启恢复（11月5日）

基于main / a1e53a16641f637cec105ce2607cbb0d74dc4fc1。基本打卡的原请求原先只在controller内存中，Page销毁后会消失；用户再次进入会生成新请求，无法可靠恢复午夜前的未知结果。本批补充本机持久恢复，不改变后台协议、服务开关或手动打卡范围。

## 行为

提交前先同步保存并回读最小请求，确认保存后再发送。重新进入时，只在同一已验证账号范围及同一环境/函数/发布配置下找回原requestId、action及placeId；请求重新冻结。恢复只显示“等待确认”，由用户点击“重试打卡”，登录、刷新、换号或页面重建都不自动重放。B看不到A的请求，回到A仍可恢复；迟到的A回执不能删除恢复项或影响B。

明确回执或明确不支持接口等拒绝后，核对原请求再清除本机项。清除失败仍保留原请求，可再次查询同一服务回执；不显示虚假成功。读写失败、损坏项、额外身份/照片字段或另一协议不会被当成空记录覆盖，页面显示中文恢复提示并停用新打卡按钮。恢复数据无法确认时，退出/更新保护继续报告有待处理操作。

账号注销经服务器确认停用后，清除本方案的该账号/该环境本机项；服务器清理进度查询也会重试本机清除。失败保留注销恢复记录和中文提示，不提前声称本机已清除，不影响其他账号。没有记录完整历史、身份凭据、经纬度或照片。
