# 11月3日导出领取失效与原格式重新申请

基线为Linghan PR #100合入后的7e5e7a57166acddbdb337700effdcd7bf8ea877f，跟踪#98/#38。成员格式/状态交互见[接收记录](../../reviews/2026-11-03-pr100-integration.md)，以下为Xiang Hong后续修正。

原问题：导出先显示ready，24小时到期或本人源变化后，真实account.downloadExport返回CONFLICT。原客户端只显示错误，仍保留可领取；原格式按钮复用可修改的exportFormat，改选JSON会将旧Markdown重新申请成JSON。

现在领取冲突后查询同一jobId的服务器状态，经验证后更新过期/失败/处理中等状态。CONFLICT也可能是内容校验问题，不能直接猜为过期；服务器仍ready则保留ready，但明确领取未完成，可重试或重新申请。普通网络失败保留任务，不自动重查/申请；ready阶段也可主动查状态。

状态结果需匹配jobId、合法状态和已知格式，只投影这三个元字段，坏响应保留已确认任务。隐藏/切号/卸载后迟到查询不回填、不写文件；未知导出申请仍用原requestId/payload重试。失效后的重新申请绑定原任务jobId和格式，新格式仍可由普通申请按钮明确发起；旧按钮不能操作后来生成的任务。仅用户主动重新申请才创建新请求，不延长旧任务有效期。
