# 普通任务持久恢复与跨日围栏

本交付对应 W4 Qizhen Chen QC01/QC02，以及 W2/W3 #38/#75 的普通任务恢复欠项。从最新 main `80e29c8e3cc6dd5eb5818b53ec250b2258687782` 单独交审；源码来自 PR #153 的本人任务增量和跨日返修，不包含 Web 后台、资料字段或身份诊断。原交审 `6beb546` 的首次未送达跨日缺口保留为失败来源。

## 行为与协议

请求发送前，本机按环境、函数、版本和不可逆账号会话作用域保存最小 `tasks.transition` 请求并读回确认。重启、隐藏、返回仅恢复提示，用户点击“重试原操作”才发送同一 requestId/payload；切号不会重放他人请求。成功及注销后的清理都需本机读回确认；存储失败保持阻塞。

新操作的 payload 为 `{taskId,transition,expectedDate,replacementTaskId?}`，expectedDate 固定为初始北京时间业务日。日期进入新回执 digest。事务内先查原回执：digest 相同就返回原日期结果；未提交且服务器业务日不同就 CONFLICT，不写入新历史、回执或任务修订，也不回填过去或预写未来。三列旧 digest 与旧客户端协议保持兼容，新版持久 outbox 不猜测无日期旧本机记录的日期，会保留内容并阻止发送。

页面只接受匹配 taskId、目标 state、expectedDate 的成功回执。明确跨日拒绝并确认本机清理后，隐藏旧选项，提示用户先“重新读取”当天状态，再明确选择新请求。网络或无效响应仍保留原请求，不自动改日期、不自动写入。原服务端不支持 expectedDate 时保持明确拒绝，前后端升级必须协调。

普通任务完成不产生地点到访记录。已有任务状态协议与 JF02 复合打卡提案仍需本人共同确认，未注册未合入的候选动作。

## 验证与边界

- 原已提交丢响应后跨午夜重开用例保留；实际 production 入口与固定原生 SDK 离线传输确认回执恢复，不重复历史或任务修订。
- 新增首次请求未到服务器即断网、重开后次日重试，以及首送达延迟至次日两条生产离线路径。断言拒绝前后数据库一致，读取不触发写入；再次明确选择才创建当天新请求。
- 覆盖非法/未来日期、篡改原日期、缺失/不符响应日期、旧本机无日期记录、账号/环境隔离、存储失败和确认注销后的清理。保留隐藏、离开保护、重复点击和旧响应断言。
- 证据为本地合成、固定 SDK 离线和 Page 控制器测试，测试通过不代表真云、手机或独立验收。完整检查结果以对应 PR 固定提交为准。

## 信息影响与生命周期

新增字段只含业务日期，其他持久字段为版本、环境命名空间、不可逆会话作用域和原请求的 apiVersion/requestId/action/taskId/transition/可选 replacementTaskId。用途是防重复、原请求恢复和跨日围栏，不保存日记正文、令牌、OpenID或角色，不增加 GPS/照片/系统权限或第三方 SDK。

每账号/环境最多一条未知请求；确认原结果或明确拒绝且完成清理读回后移除，服务器确认注销后按原作用域清理。无日期旧记录不迁移、不静默删除，核对原版本与历史后再按授权处理。退出保留同账号恢复能力，其他账号不可读/重放；不新增日志、服务端集合或私人导出范围。未改变 UGC、平台声明或正式发布状态，不声称平台生效。
