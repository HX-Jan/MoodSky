# 主持说明与研究编码（不提前给参与者答案）

先开放提问，再呈现选择；不要赞扬“正确答案”或引导选预设项。题目为需求/理解输入，不是评分测试，也不是已通过12人可用性指标。每题记录自发/追问/未问/跳过，不以缺答推断其需要。

开场：“我们想了解日常记录方法和你对界面的理解，约15分钟。不是考你，没有好坏答案，不需要私人事件。可以跳题、随时结束，并凭P编号经原邀请渠道申请撤回。参与和匿名笔记使用分别征求同意。”先核对同意、使用范围和是否已有项目P编号。

时间草案：0—2分钟说明/同意/去重；2—5分钟记录习惯/七天气；5—8分钟私人范围/保存/未知结果/草稿；8—11分钟月份、校园、自愿任务；11—13分钟导出/停用及实际可访问性；13—15分钟复述和撤回说明。可按实际情况缩减问题，不能编造问完或固定15分钟。

编码：C=真实选项选择；Q=确实逐字记录的原话；P=明确转述；O=实际观察；T=团队建议；H=待验证假设。没有录音逐字依据时不补引号。不记录姓名、年级、微信号、诊断、真实日记或编号到身份映射。

## 来源核对用参考（不是给参与者的标准答案页）

- 普通天气可单独保存，正文与标签可空；CUSTOM需要符合当前1—20码点单行规则。未接入或失败不等于已保存。
- 私人记录与CUSTOM名称不进入校园固定模拟。账号权限必须由后端验证，界面文字本身不是权限证据。
- 本地演示保存与当前正式云回执分别解释；本周不能沿用W3“所有真实保存均未开放”的旧口径。
- 未知结果可能已提交，应恢复原requestId与输入；明确拒绝、冲突和未知分别记录，不能把重试原操作改成新请求。
- 手动打卡是用户自行确认，不获取GPS，不证明核验到场；新源码存在不证明新云集合已部署或线上0.3.0已有该功能。
- 自愿任务可不选/跳过，不改日记、不扣分；完成必须与跳过区分。
- 领取过期、账号停用、后台清理完成和用户手机已保存副本是不同事情；不得称一点击就清掉全部备份。
- 可访问性只问真实体验；没读屏/没放大选择未测，不能默认“无困难”。

先记录其理解，再按需要解释这些边界；保留解释前后差异。若界面/模式与参考不符，以固定构建实际能力核实，不让回答迎合当前源码。HTML只在内存检查选择，不发送答卷；实际研究记录由主持在受控渠道保存，GitHub只收匿名化必要汇总、模板和获许可摘录。
