# W4 QT01 账号隔离与竞争复核

## 范围与基线

本次独立复核覆盖私人记录、回顾、导出、手动打卡和账号停用相关的账号边界与异步竞争。
基线为 `66be660828a4e09e253720028a670d0912c4794f`；运行环境为 Node `v24.22.1` 的
本地合成仓储及 SDK 离线替身。业务日期和天气规则使用当前七类天气：`SUNNY`、
`PARTLY_CLOUDY`、`CLOUDY`、`RAINY`、`STORMY`、`TYPHOON`、`CUSTOM`；
`CUSTOM.weatherName` 按 1—20 个 Unicode 码点处理。

## 独立复核结论

本地用例确认：服务端身份以可信上下文解析，客户端提交的 `ownerId`、`openid`、
`accountId`、角色和信封身份字段不能改变操作归属；停用账号在下一次私人请求即被围栏
拒绝；旧会话的迟到成功、失败或授权错误不能覆盖新账号状态。未知写入保持原
`requestId` 和原始 payload，跨账号不重放。

| 场景                 | 核查点                                                                                | 本地结果 |
| -------------------- | ------------------------------------------------------------------------------------- | -------- |
| A/B 读取、修改、删除 | 数据和响应都按服务端解析出的账号归属；B 不能读取或写入 A 的私人对象                   | 通过     |
| 首次并发创建         | 16 个并发调用在唯一键冲突或丢失响应后收敛为一个初始化账号                             | 通过     |
| 同日手动打卡         | 同一账号同日去重；原请求可重放；A 的导出不含 B 的打卡                                 | 通过     |
| 切号和迟到响应       | A 的迟到成功、网络失败、`UNAUTHENTICATED`、`ACCOUNT_DISABLED` 和 `FORBIDDEN` 不影响 B | 通过     |
| 停用围栏             | 停用账号不能重建为 active，私人读取/写入拒绝；清理只处理该账号对象                    | 通过     |
| 页面草稿与回顾缓存   | 登出、A→B→A、隐藏和卸载均清除旧私有状态，迟到保存不恢复到新会话                       | 通过     |

## 关键执行记录

1. `account-identity` 检查无可信身份、客户端伪造身份、停用身份和受限回执；所有身份
   字段均在进入仓储前拒绝或忽略。
2. `account-provisioning` 在内存与锁定 SDK 替身中覆盖首次并发、唯一键冲突和丢失新增
   响应；确认不产生第二个账号。
3. `journal-snapshot-concurrency`、`session-races`、`week4-hong-session` 和
   `week4-closure-scope` 覆盖异步结果晚到、切号、隐藏、恢复和停用竞争。
4. `campus-checkin-candidate`、`campus-checkin-page` 与 `manual-campus-checkin` 覆盖
   本人完成记录、相同请求重试、同日去重、跨日和历史重开读取。

上述测试包含在 [定向 TAP 日志](evidence/qt01-qt03-targeted-final.tap) 的 266 项通过结果中。
九组联调的账号隔离组也通过，见 [团队联调结果](evidence/team-integration.json)。

## 证据边界

本记录中的 A/B、运营者、停用身份和迟到回调均为本地独立夹具与 SDK 离线替身。真实
双微信账号、真实云端身份与实体设备操作需要在获得相应测试条件后另行保留操作证据；
本地结果不替代该层记录。
