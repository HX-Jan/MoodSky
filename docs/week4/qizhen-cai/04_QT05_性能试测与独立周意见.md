# W4 QT05 性能试测与独立周意见

## 测量条件

性能试测基于 D30 七天气数据集：30 条记录、每条 200 个 Unicode 码点正文、固定标签
`REST`，涵盖六种固定天气和带名称的 `CUSTOM`。测量时间为
2026-11-07T12:16:24.874Z 至 2026-11-07T12:16:26.497Z；基线为
`66be660828a4e09e253720028a670d0912c4794f`。

环境为 Windows x64、Node `v24.22.1`、Intel Core i5-13500H、16 逻辑 CPU、31.7 GiB
内存。页面以 Node VM 加载实际 Today/Universe 页面源码，并以同步 `setData` 替身观察
数据状态就绪；不包含 WXML/原生渲染、微信启动、网络、云函数或真实数据库延迟。

## 页面逻辑测量

每组 5 次，共 20 条页面样本；同进程组另有每页 5 次未计入的预热。C 表示新的 Node
进程，W 表示同进程。数值为页面逻辑就绪时间，不是手机首屏可交互时间。

| 组别  | 页面与条件       | 成功/尝试 | 中位数 ms | 均值 ms | 最大值 ms |
| ----- | ---------------- | --------: | --------: | ------: | --------: |
| L-T-C | Today，新进程    |       5/5 |     7.454 |   7.551 |     8.132 |
| L-T-W | Today，同进程    |       5/5 |     1.061 |   1.082 |     1.146 |
| L-U-C | Universe，新进程 |       5/5 |     9.306 |   9.357 |     9.711 |
| L-U-W | Universe，同进程 |       5/5 |     1.094 |   1.115 |     1.270 |

新进程的进程启动到首条结果中位数为 Today 82.043 ms、Universe 80.951 ms；该值同时包含
Node 启动、模块导入、夹具和进程通信，不能与同进程组直接比较。

## 批量操作测量

每个操作组执行 20 批，每批 100 次；每组另有 100 次预热。四个操作组共计 8,000 次
已测操作，全部成功。

| 组别       | 操作              | 每批均值中位数 ms | 每批均值最大值 ms |
| ---------- | ----------------- | ----------------: | ----------------: |
| Q-GET30    | 30 条记录读取     |            0.1071 |            0.1212 |
| Q-CALENDAR | 两个月月历读取    |            0.0424 |            0.0481 |
| Q-ARCHIVE  | 两个月档案读取    |            0.0427 |            0.0482 |
| Q-ANALYSIS | 30 天分布与时间线 |            0.0801 |            0.0913 |

原始样本、D30 数据、源码哈希及运行输出见 [performance](evidence/performance/)。

## 正式实体设备记录口径

正式记录沿用 `tools/qizhen/performance-summary.js` 的固定口径：Android/iOS 各分冷启动和
热启动四组，每组至少 5 次，共至少 20 次。每条记录固定设备、系统、微信、构建 SHA、
网络、D30 数据集、启动证据、同一视频或时钟的 T0/T1、操作成功证据和失败原因。失败与
超时留在分母，`invalid` 记录保留排除原因；不同设备或网络不混入同一统计组。

## 独立周意见

1. 当前主干的本地质量门已通过：1,410 项测试、lint、格式、结构、文档链接和类型检查均为
   0 失败。
2. QT01—QT03 的定向复核覆盖了账号围栏、异步回调、导出清理和恢复路径；这些本地结果与
   团队联调结果一致。
3. D30 试测适合用于比较同一源码的页面逻辑回归，不用于判断手机首屏性能或 2.5 秒目标。
4. 实体设备测量应在固定构建和固定网络下采集，并按上述四组分开统计；真实云、设备和
   人机交互证据需与本地 Node VM 结果分列。
