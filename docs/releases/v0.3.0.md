## 从GitHub使用

本机使用Node.js 24；先完成[组员手册](../../GETTING_STARTED.md)。默认开发配置关闭云能力，可通过本地合成联调开发，无需生产密钥。普通导入仓库根目录只使用开发入口，不会自动变成正式云客户端。

需要准备正式构建时，从仓库根目录执行：

```powershell
npm.cmd ci
npm.cmd run setup
npm.cmd ci --prefix cloudfunctions/moodsky
npm.cmd run cloud:prepare
npm.cmd run check
npm.cmd run release:package -- "C:\MoodSky-builds\0.3.0-candidate-001"
```

最后的路径必须是仓库外一个尚不存在的绝对目录；换成自己机器上的可写位置。打包只生成文件，不调用微信、部署或上传。导入生成目录中的project.config.json，云函数目标默认是moodsky-release及moodsky-release-maintenance，不是旧moodsky入口。新包manifest中的uploaded/deployed/publicRelease为false，表示这份新生成包尚未执行对应操作，不否认原0.3.0已上线。

默认正式目标对应AppID wxf602e991ff44e6c8、环境mood-sky-d5gqy3spkff37566d。主业务超时30秒，维护60秒，调度为`0 */5 * * * * *`（10月30日读回）。只准备文件不需要修改平台设置。后续部署需明确授权、备份、检查包哈希；保留现有稳定身份密钥，否则同一用户会映射为不同账号。

仓库不含runtime.local.json、个人environment.local.js或生产密钥。打包器不从本机私密配置复制密钥；服务端无明确有效配置时保持关闭。依赖锁保留主干follow-redirects 1.16.2修复，原上线包锁文件为1.16.1；本轮没有下载正在运行的依赖，不能声称线上已完成该依赖升级。
