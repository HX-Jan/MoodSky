# MoodSky v0.5.0

2026 年 11 月 11 日。版本以 GitHub `v0.4.0` 和后续通过审查的主干为来源。客户端、云函数构建及打包清单版本均为 `0.5.0`。

- 校园提供福大旗山校区五个地点和文字方位。用户自行到达后点击完成，支持本人当天状态、同日去重、原请求恢复和分页历史。旧服务缺少状态接口时仍可浏览推荐，页面明确提示打卡暂不可用，已有历史保留独立入口。
- 任务保留建议、本人状态和历史，已有确认回执可在重试时恢复。合入 Qizhen Chen 的入口、只读范围和确认状态修复。发布者按目标服务支持范围选择打包参数 `enabled`、`readOnly` 或 `closed`。
- 保留七天气、微信登录、右上角原生分享和首页 MoodSky 表头。纳入下拉刷新、回顾与详情同步、偏好回执校验和账号切换保护。

## 构建与联调

在仓库根目录先运行 `npm run cloud:prepare`，再运行 `npm run check`。运行 `npm run release:package -- <新绝对路径> enabled` 生成保留普通任务入口的联调包。使用包根目录的 `project.config.json` 导入微信开发者工具。`manifest.json` 记录提交、任务模式和客户端及两支云包的指纹。

发布人核对目标云的 `place_checkins`（`ownerId + placeId + date` 联合唯一）与 `campus_checkin_states`（`ownerId` 唯一），两表均禁止客户端直接读写。先准备同版维护函数，再更新业务函数。保持新增打卡暂停，用授权测试号完成本人历史、导出和注销清理核对后再开放。每次切换后核对实际 `system.health` 返回的 `campusCheckinWritesPaused`，并在真机复测。遇到写入故障时先暂停新增，保留原回执、历史、导出和清理；有新打卡数据后勿直接回退到不支持这些数据的旧函数。

固定 `v0.5.0` 标签的云包从哪里读取密钥，就从哪里读取 `MOODSKY_CAMPUS_CHECKIN_WRITES_PAUSED`。如果使用服务器部署文件，单独更改平台环境变量不会生效。后续源码修复了这个限制：平台暂停开关可以覆盖部署文件中的值，同时继续使用文件里的密钥。修复后的包默认暂停；只有明确设为 `false` 才开放。服务器密钥配置的优先级及缺失时关闭业务的规则保持不变。部署前用清单核对云包来源提交，并确认客户端与后端各自使用的版本。
