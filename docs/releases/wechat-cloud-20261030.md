## 服务器私密配置

CLI部署工具没有环境变量编辑入口。本轮增加可选的服务器文件配置：仅部署目录中的 `runtime.local.json` 可以提供该配置；源仓库、公开候选包和小程序代码不含此文件或真实密钥。文件必须绑定预定AppID、环境和存储版本，并提供三个独立随机密钥，否则业务仍关闭。任何显式平台MOODSKY配置优先，`MOODSKY_PRODUCTION_ENABLED=false`可关闭文件配置；部分平台配置错误时也保持关闭。

真实密钥只在本机受保护的部署目录和服务器函数包中使用，额外保存当前Windows用户可解密的备份，不输出到日志、聊天或Git。身份密钥必须稳定保留，后续部署复用，不能随构建重新生成。具有云函数源码管理权限的人可访问服务器配置，运营人员应按现有权限管理；这里没有开放新的数据库权限或公共密钥入口。

`timer.config.json`声明每5分钟执行一次，打包器将它复制为维护函数目录下的`config.json`。依照[CloudBase定时触发器文档](https://docs.cloudbase.net/cloud-function/timer-trigger)，微信开发者工具还需单独上传触发器。本次代码和配置文件不是已运行证据；只有实际触发记录与脱敏维护结果核对后，才将外层timerConfirmed改为true。

维护日志只输出成功/失败和计数，不输出事件原文、账号、密钥、导出正文或清理凭证。客户端没有改变，不因这项服务器变更自动重传已经上传的0.3.0包。手机验收、维护定时器实际执行和正式平台提审仍分别留证。

真实18:30定时调用已经发生，但返回FORBIDDEN；平台日志的200只表示调用完成，不表示维护成功。因此补充[CloudBase文档中的TRIGGER_SRC定时来源](https://docs.cloudbase.net/cloud-function/function-configuration/env)接法，并在服务器日志输出各个授权条件的布尔值以定位平台差异，不输出上下文或event的原值。该补充仍需部署与真实定时复测；不能提前改为定时维护已完成。

18:50真实调用的布尔诊断表明，新鲜身份、固定环境、定时来源、无用户身份和固定触发器名称均匹配，只有额外的`event.Type === 'Timer'`格式假设失败。因此移除这项通用SCF事件格式假设，授权仍依据平台本次调用元数据和固定名称。此前合成测试中“可信定时来源仍因Type字段不符而拒绝”的断言随真实平台契约修订；新增无Type格式的真实形状回归，同时验证同一event在微信客户端、错误环境、错误名称下仍拒绝，不能用event自称Timer获得权限。尚需部署后以真实定时业务结果复测。
