## 1. 已确认的范围

[新批次实际报告](w1-h03-report-retention-validation.json)完整保存了 17 项结果。失败项是 V03-create、V03-edit、V03-edit-delete、V04-same-input、V05-different-input，安全错误码均为 -501001，其余 12 项通过。本报告不解释旧批次的未知逐项结果。

当前报告只有场景编号、通过状态、安全错误码与回调数，没有失败发生在哪个数据库调用、原始后端符号码或并发两侧各自的最终结果。因此“并发事务冲突在 SDK 中丢失错误类型”只是待核实假设；不能把 -501001 直接改写为 CONFLICT 或成功。

## 2. 锁定 SDK 的离线复现

使用项目已安装的 wx-server-sdk 4.0.2 和 @cloudbase/database 1.5.1，保留真实事务及文档 API 封装，只把底层数据库传输替换为严格列举操作的本地夹具。所有入参和错误均为合成，未请求云端或修改依赖。5 组断言全部通过。

| 注入位置与合成错误                             | 实际向调用者暴露           | 实际事务回调次数 | 结论边界                                           |
| ---------------------------------------------- | -------------------------- | ---------------: | -------------------------------------------------- |
| 文档 update 返回 DATABASE_TRANSACTION_CONFLICT | errCode:-501001，code 缺失 |                1 | 本地可复现类型转换后不进入符号码冲突重试           |
| commit 第一次返回同一符号冲突，第二次成功      | 最终成功                   |                2 | 底层仍识别提交阶段的符号码并重新执行回调           |
| 文档 update 返回 SYS_ERR                       | errCode:-501001，code 缺失 |                1 | 同一数字也能表示系统错误                           |
| 文档 update 返回未映射的合成符号码             | errCode:-501001，code 缺失 |                1 | 未知后端错误也可能落入同一数字                     |
| 文档 update 返回 DATABASE_REQUEST_FAILED       | errCode:-502001，code 缺失 |                1 | 该数字是一般数据库请求失败，不能单独证明唯一键类型 |

离线证据：[结构化结果](../../test-reports/2026-10-15/artifacts/2026-10-15-H03-sdk-error-characterization.json)；可复核脚本：本地复现（原本机材料，未随仓库发布）。这些 5 项是补充离线检查，不计入原项目 62 项测试，也不声称云端 5 个失败已修好。

实现依据来自锁定的本地依赖：wx-server-sdk 的数据库 error-checker 会将未映射的符号码转为 SYS_ERR 数字；@cloudbase/database 的 runTransaction 只对 code 为 DATABASE_TRANSACTION_CONFLICT 的错误进入冲突重试。此处为当前锁定版本的行为，没有修改 node_modules 或据此升级 SDK。

2. 选择能保留确切符号码的公开服务端 API 边界，先用锁定 SDK 和本地传输夹具核对；不依赖字符串解析错误消息，不把所有 -501001 或 -502001 一律重试。
