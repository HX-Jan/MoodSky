## 1. 本次请审查的改动

最近正式 system.health 真实调用返回 INVALID_REQUEST。本地标准四字段请求能通过，附加 userInfo/tcbContext 会被入口白名单拒绝；正式云端实际入参仍未观察，附带字段是待核实原因。当前修正针对已复现的入口兼容问题，不声明云端健康已恢复。

候选只在云入口过滤两个已知的顶层附带字段，其值不参与身份、角色、action 或业务输入。随后继续使用原请求校验和 SDK 可信上下文。对已有业务和权限的预期影响如下：

| 检查                                        | 当前正式代码         | 拟应用后的本地行为                   |
| ------------------------------------------- | -------------------- | ------------------------------------ |
| 标准四字段健康请求                          | 本地成功             | 继续成功                             |
| 健康请求附带 userInfo/tcbContext            | 本地 INVALID_REQUEST | 忽略这两个字段后按原四字段校验       |
| 其他未知顶层字段                            | 拒绝                 | 继续拒绝                             |
| 元数据伪造身份，没有 SDK 可信身份           | 私人入口拒绝         | 继续 UNAUTHENTICATED                 |
| 停用账号、普通用户调用运营入口              | 拒绝                 | 继续拒绝                             |
| payload 保留身份字段、错误版本、非法请求 ID | 拒绝                 | 继续拒绝                             |
| 真实记录等未实现业务                        | NOT_IMPLEMENTED      | 继续按当前适配器和占位模块返回未实现 |

本次不会在入口实现账号创建、记录保存、并发重试或回顾业务。H03 的 5 项并发失败与正式健康兼容分别处理。
