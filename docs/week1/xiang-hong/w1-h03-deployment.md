## 3. 操作者登记与调用边界

控制字段只接受 `operation`、`runId`、清理时的 `confirm`；后续获批兼容修正会忽略 userInfo/tcbContext 附带字段，不从其内容获取控制指令或身份。它从 wx-server-sdk 的可信 getWXContext 读取 ENV/APPID/OPENID，同时核对固定环境和 AppID。请求中的 ownerId、OPENID、集合名、正文、token 或指纹均会拒绝，不能借测试入口指定真实账号或业务资源。

1. 初次部署后，在负责人本人已登录的小程序微信上下文中调用 `identify`。云控制台的普通服务端测试调用可能没有可信微信 OPENID，届时应拒绝，不通过伪造 event 字段补身份。
2. identify 只返回当前调用者 OPENID 的派生指纹，不查询数据库，不注册其他成员，不返回原 OPENID。拥有者私下确认这是自己的调用后，在云函数环境变量中填写该指纹；不要把实际指纹或登录信息贴到公开文档、聊天截图或 GitHub。
3. 未填写、填写错误、另一个账号调用或环境/AppID 不符时，run/inspect/cleanup 等数据库操作均返回 FORBIDDEN，且不打开数据库连接。
4. 代码没有默认允许的真实账号或硬编码登录凭证；后续安全诊断版只打印固定阶段日志，不打印请求或身份值。这个指纹来自平台可信上下文，不能作为 event 字段提交来获得授权。

如需要登录微信开发者账号，由拥有者手动完成；执行时会弹窗说明所需操作。本步没有重新登录、查询成员权限或取得真实操作者指纹。

## 4. 待执行的 17 个基础场景

这些场景已写入包，但尚未在云端执行。内部版本/回执模型用于验证数据库能力，测试中的账号和正文固定为合成值，不提供通用 journal.upsert/delete 入口。

| 场景                 | 要检查的行为                                                    |
| -------------------- | --------------------------------------------------------------- |
| V01-commit           | 日记、账号来源版本和无正文回执一起提交                          |
| V06-afterJournal     | 改记录后、登记回执前注入故障，整笔回滚                          |
| V06-afterReceipt     | 登记回执后、提交前注入故障，整笔回滚                            |
| V02-journals         | 同 owner/date 的第二条插入被拒绝；不同日期的对照插入可成功      |
| V02-receipts         | 同 owner/action/ID 的第二条插入被拒绝；不同 ID 的对照插入可成功 |
| V03-create           | 同日两个新建 ID，只有一条有效记录                               |
| V03-edit             | 同版本两个编辑，不能静默覆盖                                    |
| V03-edit-delete      | 同版本编辑与删除竞争，只接受一个变更                            |
| V04-same-input       | 同 ID/同输入并发，回执只对应一次变更                            |
| V04-response-loss    | 提交后模拟响应丢失，重试不增加版本                              |
| V05-different-input  | 同 ID/不同输入并发，第二输入不能写入                            |
| V05-rejection-replay | 已绑定的业务拒绝不能自动变成新操作                              |
| V07-boundary         | 今天前 29/30 天、未来新建及成功后的跨日重试                     |
| V07-old-edit         | 窗口外已有旧记录仍可编辑                                        |
| V07-midnight         | 北京时间午夜前后的今天边界                                      |
| V08-delete-recreate  | 明确移除内容字段；重建版本前进；旧请求不复活正文                |
| V08-empty-delete     | 空删除回执重放不能删除后来新建的记录                            |

V02 保存安全的 SDK 错误码并做正向对照，不输出平台原错误文案或猜测错误含义；错误码与“重复唯一键”的准确映射仍标为 errorMappingConfirmed:false，须结合索引状态和实际 SDK 返回由 Xiang Yu 复核。暂不把一个通用数据库错误当作已确认的重复键错误。

所有场景使用包内固定的合成服务器时钟，调用者不能改日期或注入时钟；它不是生产接口对真实当前时间的验收。响应丢失在提交后主动注入，并未执行真实网络断连实验。

V09 回顾/装饰/迟到响应、V10 实际导出/链接/文件撤销、V11 正式可信账号解析和停用竞争、V12 回执过期/密钥轮换/备份恢复仍待相应模块和方案接入。探针使用本次内存生成的摘要密钥，只验证同次实验的回执绑定；没有实现生产密钥轮换、长期回执或备份恢复。因此报告固定保留 technicalValidationComplete:false 和 productionJournalImplemented:false，即使基础断言全部成立也不能代替 H03 全部验收。
