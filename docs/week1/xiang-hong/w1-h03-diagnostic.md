## 1. 当前结论及此前指引的更正

拥有者确认的是“能选到 moodsky-h03-probe，但日志记录为空”，不是函数下拉列表缺少该函数。重新查询云函数列表仍有 moodsky、moodsky-h03-probe；本次只读 identify 调用返回 INVALID_REQUEST 和请求编号 3c8c831e-36e0-41e0-a63f-c1c23077665b，结果只有 ok/error 字段，没有基础业务 API 的版本及关联 ID。这些是调用结果证据，尚未关联到实际服务端日志。

诊断版部署前的探针入口和合成实验源码没有 console.log/info/warn/error 输出，也没有输出请求入参。此前让拥有者从日志寻找原始入参不合适，不能把未确认存在的入参查看能力当作可用步骤。[CloudBase 官方日志说明](https://docs.cloudbase.net/cloud-function/debugging/log)介绍标准输出采集，[服务调用日志说明](https://docs.cloudbase.net/logger/tracelog)另介绍平台调用记录；二者应分别核对。没有自定义输出可以解释找不到我们打印的入参，但不能单独解释整张调用记录列表为空。

当前日志时间/版本/状态筛选及实际投递设置没有完成核验，不能据空列表断言函数不存在、调用从未发生，或平台日志一定正常。窗口自动操作受最小化、用户输入保护和置前失败影响，尚未稳定读到日志页。本提案改用直接响应诊断定位格式拒绝，并用固定日志标签帮助后续核对投递，不再依赖拥有者寻找原始个人数据。

## 2. 拟改动及隐私边界

补丁只修改 [探针入口](../../../tools/h03-probe/index.js)，并新增 tests/h03-diagnostic.test.js 的 5 项验证；具体内容见[已应用补丁](w1-h03-diagnostic.patch)。没有继续扩大允许字段，没有修改 getWXContext 身份来源、操作者匹配、集合范围或 17 项实验逻辑。

1. 云函数入口写出固定标签 `[h03-control-shape-20261014] entry`；后续只输出 control-accepted、control-rejected 或 execution-failed 这样的固定阶段词。日志不包含 event、字段名、字段值、正文、OPENID、指纹或平台错误文案。日志输出失败不能改变拒绝或授权结果。
2. 仅当请求在控制格式校验阶段被拒绝时，原 ok:false / INVALID_REQUEST 结果增加 diagnostic。它返回接收类型、顶层字段名、字段数量、operation/runId 类型及是否属于已知操作等布尔值，不返回操作值、批次值、嵌套内容或身份值。
3. 字段名只允许短字母/数字/下划线/美元符号名称，长度最多 48，最多返回 16 个；其余仅报告省略数量。名称来自该次调用自身的输入结构，不能据此把一个字段认定为可信平台数据；所有校验仍拒绝原请求。
4. diagnostic.databaseAccessed:false 只在控制校验确已拒绝、尚未打开数据库的路径返回。已通过格式的请求继续走原可信环境/AppID/OPENID 和操作者授权检查，不附加这个控制拒绝诊断。

这样，即使日志页暂时不可读，也可以从拥有者本人发起的固定只读调用中看到实际结构是否为对象、操作字段是否存在、有哪些额外字段。诊断标识同时帮助区分新包结果与旧包结果；并不直接修复 INVALID_REQUEST。任何后续兼容修改仍应依据实际结果另行准备并审查，不按猜测放宽白名单。
