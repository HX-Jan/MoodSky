## 2. 五个入口共同规则

请求、成功与失败外层沿用 `{apiVersion,requestId,action,payload}` 及现有 ApiResult；失败无合法 ID 时 requestId 为 null 的共享类型缺口沿用 H02 待办。下面示例中的对象均为 payload 或成功的 data，完整信封见[合成样例 JSON](w1-h04-examples.json)。

- 只读取可信平台身份解析出的 active 本人账号，不接受 ownerId、uid、角色或身份字段指定对象。无可信身份、停用及无权限沿用现有错误码；后台资料运营身份不获得读取私人回顾的权限。
- 日期按 Asia/Shanghai 业务日；month 为真实四位年份和 01—12 月的 YYYY-MM，windowDays 仅为数字 7、30、90。服务端决定今天；不接收客户端 now/startDate/endDate 改变窗口。合法未来月份返回实际空数据，不能制造记录。
- 日记源只取本人有效原始记录，排除删除态、其他账号及范围外记录。所有视图使用同一来源，不持久复制正文到卡片或统计表；未记录日期留白，不填成 CLOUDY、不插值、不评分。
- 查询拟严格拒绝未约定 payload 字段；calendar/monthArchive 只有 month，distribution/timeline 只有 windowDays。缺失参数、null、错误类型、不真实月份和额外字段拟返回 INVALID_INPUT；保留外层身份字段的 INVALID_REQUEST 行为。
- sourceRevision 拟为本次读取的本人 journalRevision 非负安全整数，只用于判断来源新旧，不是授权凭证或记录版本。跨多次查询如何获得一致来源需审查；不能把分次查询后的同名字段当作原子快照。

## 3. 输入、成功结果和样例

下列数据完全为合成：固定服务器时钟 2026-10-15T04:00:00.000Z，业务日 2026-10-15；三条有效记录在 10 月 9、12、15 日，天气分别为 SUNNY、RAINY、SUNNY。夹具还含一条已删除记录、另一合成账号记录及上月记录，用于核对过滤。sourceRevision:12 是样例值，未取自真实账号。

### 3.1 review.calendar

输入 `{ "month": "2026-10" }`。拟返回：

```json
{
  "month": "2026-10",
  "entries": [
    { "id": "synthetic_h04_09", "date": "2026-10-09", "weather": "SUNNY" },
    { "id": "synthetic_h04_12", "date": "2026-10-12", "weather": "RAINY" },
    { "id": "synthetic_h04_15", "date": "2026-10-15", "weather": "SUNNY" }
  ],
  "recordCount": 3,
  "sourceRevision": 12
}
```

entries 按日期升序，仅返回有记录日，不返回正文、标签或内部 ownerId。前端生成真实月份网格，把缺失日期保持留白；空月 entries:[]、recordCount:0。一天最多一项；重复日期视为数据异常，不能让 UI 随机覆盖。点击有效日期后按 H02 journal.get 取本人详情，并核对仍是同一 entryId，避免删除重建后误开旧卡。

### 3.2 review.distribution

输入 `{ "windowDays": 7 }`。窗口为今天及此前 6 天，起止日期都包含。30/90 天分别同理，不以有记录天数替代窗口长度。拟返回：

```json
{
  "startDate": "2026-10-09",
  "endDate": "2026-10-15",
  "windowDays": 7,
  "recordCount": 3,
  "sourceRevision": 12,
  "bins": [
    { "weather": "SUNNY", "count": 2 },
    { "weather": "PARTLY_CLOUDY", "count": 0 },
    { "weather": "CLOUDY", "count": 0 },
    { "weather": "RAINY", "count": 1 },
    { "weather": "STORMY", "count": 0 }
  ]
}
```

五类顺序复用共享常量，即使计数为 0 也保留。分母始终为 recordCount；示例晴天为 2/3、雨天为 1/3，不是 2/7 和 1/7。不传服务端小数百分比，前端统一显示精度并同时提供“2/3 条”等文字，避免累计舍入被误认为多一条记录。空数据五类 count 均为 0，显示中性空态，不计算 0/0。

### 3.3 review.timeline

输入 `{ "windowDays": 7 }`。拟返回：

```json
{
  "startDate": "2026-10-09",
  "endDate": "2026-10-15",
  "windowDays": 7,
  "recordCount": 3,
  "sourceRevision": 12,
  "items": [
    { "id": "synthetic_h04_15", "date": "2026-10-15", "weather": "SUNNY" },
    { "id": "synthetic_h04_12", "date": "2026-10-12", "weather": "RAINY" },
    { "id": "synthetic_h04_09", "date": "2026-10-09", "weather": "SUNNY" }
  ],
  "trendEligible": true
}
```

items 按业务日期降序，不按 createdAt 或编辑时间排序。缺失日期不合成天气；0 条为空数组，2 条时 trendEligible:false。true 只表示达到至少 3 条的数量门槛，不能直接输出上升/下降结论、天气分数或健康评价。趋势文案或算法另行确认；本稿不新增趋势结论。

### 3.4 review.monthArchive

输入 `{ "month": "2026-10" }`。拟返回：

```json
{
  "month": "2026-10",
  "cards": [
    { "id": "synthetic_h04_15", "date": "2026-10-15", "weather": "SUNNY" },
    { "id": "synthetic_h04_12", "date": "2026-10-12", "weather": "RAINY" },
    { "id": "synthetic_h04_09", "date": "2026-10-09", "weather": "SUNNY" }
  ],
  "recordCount": 3,
  "sourceRevision": 12,
  "cardTextPreview": false
}
```

卡片按日期降序，与 timeline 使用相同记录 ID；编辑更新原卡，重建使用新 ID。默认响应不含正文或 textPreview，不能只在界面中用样式隐藏已返回的全文。空月 cards:[]、recordCount:0、cardTextPreview:false。

主动开启正文预览的字段、截断长度与偏好适配尚未共同确认，暂不加入本次拟定 payload。正式实现时必须同时核对服务端本人偏好和当前明确请求；客户端参数不能绕过已关闭的偏好。未完成这部分前只能实现默认隐藏和本人详情路径，不能宣布 F09 全部完成。

现有 monthArchive 只接收指定月份，不含月份目录分页。长期档案的月份列表入口、游标和跨页删除失效仍是接口缺口，不能为演示自行新增公共 action。

### 3.5 review.decorations：单 action 的 operation 提案

本稿优先提出保留一个现有 action，以 operation 区分 get、replace、reset，供共同评审；尚未改注册表。当前 mutates:true 对整个复合 action 的标记需与审计/限流消费者一起核对，不能把 get 错当成数据变更。

| operation | 输入                                           | 成功 data                                      | 关键行为                           |
| --------- | ---------------------------------------------- | ---------------------------------------------- | ---------------------------------- |
| get       | month                                          | month、version、stickers、backgroundId         | 不创建空文档、不增加版本、不写回执 |
| replace   | month、expectedVersion、stickers、backgroundId | 相同字段，version 为新版本                     | 完整替换装饰配置；不修改日记       |
| reset     | month、expectedVersion                         | month、version、空 stickers、null backgroundId | 只重置装饰；不修改偏好和记录       |

未存在配置的读取样例：payload `{ "operation": "get", "month": "2026-10" }`，data `{ "month": "2026-10", "version": 0, "stickers": [], "backgroundId": null }`。

完整替换样例：

```json
{
  "operation": "replace",
  "month": "2026-10",
  "expectedVersion": 0,
  "stickers": [{ "stickerId": "SYNTHETIC_STICKER_A", "targetEntryId": "synthetic_h04_15" }],
  "backgroundId": null
}
```

对应拟成功 data 为 `{month:"2026-10",version:1,stickers:[{stickerId:"SYNTHETIC_STICKER_A",targetEntryId:"synthetic_h04_15"}],backgroundId:null}`。此素材 ID 只是合成示例，未登记为真实可用素材。重置样例 payload `{operation:"reset",month:"2026-10",expectedVersion:1}`，data `{month:"2026-10",version:2,stickers:[],backgroundId:null}`。

- 拟 version 为非负安全整数，缺省文档读为 0；首次 replace 传 0，之后传当前版本。已有文档版本竞争返回 CONFLICT，不能跟随新版本覆盖。无配置的 reset 传 0 拟返回 version:0 空态且不建文档；有配置的 reset 清空并推进版本。
- replace/reset 复用同一 requestId 和原 payload 做不确定结果重试，服务端回执处理需要沿用 H03 原输入绑定原则，并单独验证。get 不写去重回执。旧重试不得恢复删除后的 entry 关联。
- 拟 sticker 只能来自经核验素材目录，不接受 URL、脚本、用户上传路径或任意坐标配置。每项只有 stickerId 和可选 targetEntryId；无 targetEntryId 为独立月份装饰，有值则须是本人该月当前有效 entryId。未知字段、重复的同一贴纸/目标组合、他人/已删/跨月目标拟返回 INVALID_INPUT，不暴露对象是否属于他人。
- 需求限制为静态贴纸最多 6 个、背景最多 2 个；素材目录和单月放置数量含义需 Zhifeng/Jiaqi 确认。当前提案是目录最多 6 种贴纸、2 种背景，单月最多 6 项贴纸且只选 1 个背景；此放置上限属于待审提案，不能据已有常量宣布产品约定已定。
- 装饰关闭属于偏好，不删除配置、不改日记。素材加载失败用天气文字和默认背景降级；独立月份装饰不随某一天记录删除而全部清空。关联旧 entryId 的装饰立即过滤，物理关联清理按 H03 处理。

## 4. 类型与消费者变更清单

以下仅为本文内类型草稿，尚未导出到共享 types.d.ts。WeatherCode、BusinessDate 复用已有类型；MonthString 和安全整数仍需运行时校验。

```typescript
type MonthString = string;
type ReviewWindow = 7 | 30 | 90;
interface ReviewEntryMark {
  id: string;
  date: BusinessDate;
  weather: WeatherCode;
}
interface MonthReviewInput {
  month: MonthString;
}
interface WindowReviewInput {
  windowDays: ReviewWindow;
}
interface WindowReviewMeta {
  startDate: BusinessDate;
  endDate: BusinessDate;
  windowDays: ReviewWindow;
  recordCount: number;
  sourceRevision: number;
}
interface DecorationItem {
  stickerId: string;
  targetEntryId?: string;
}
type DecorationInput =
  | { operation: 'get'; month: MonthString }
  | {
      operation: 'replace';
      month: MonthString;
      expectedVersion: number;
      stickers: DecorationItem[];
      backgroundId: string | null;
    }
  | { operation: 'reset'; month: MonthString; expectedVersion: number };
```

拟结果类型对应第 3 节样例；是否将共同字段抽成接口由实际消费者需要决定，不为文档增加生产依赖。需要同步复核的范围包括 docs/api.md、共享 types/validation/contracts、回顾后端、review service、Universe 页面、偏好入口和测试。已注册 action 名及 private 访问范围保持现状；共享变更经接口审查后才应用。

## 5. 删除、晚到响应与异常验收清单

| 编号 | 场景                                         | 拟验收结果                                      |
| ---- | -------------------------------------------- | ----------------------------------------------- |
| R01  | 空月、跨月、2028 闰年 2 月、非法 2026-13     | 真实日期网格；非法月份拒绝；无记录留白          |
| R02  | windowDays 为 7/30/90，字符串、0、8、null    | 仅三种数字合法；服务端算含今天窗口              |
| R03  | 同一夹具的月历/卡片/分布/时间线              | 同源有效记录一致，统计总数正确                  |
| R04  | 0/2/3 条记录                                 | 空态不除零；少于 3 条不输出趋势结论             |
| R05  | 编辑同日记录后刷新                           | ID 不变，天气和分类计数更新；不生第二张卡       |
| R06  | 删除及重建同日记录                           | 五个入口不返回旧 entryId/正文/关联；新代际可读  |
| R07  | 请求 A 开始、删除完成、旧 A 响应晚到         | 客户端废弃旧视图代次响应，不能重新渲染已删数据  |
| R08  | 账号 A 切 B 后 A 响应晚到                    | 清空 A 状态并拒绝旧会话响应；缓存不得混用       |
| R09  | 停用账号或伪造 uid/ownerId/角色              | 门禁拒绝，不能读取原回顾                        |
| R10  | 默认/关闭正文预览                            | 响应无正文和 textPreview；详情仍须本人门禁      |
| R11  | 装饰 get/replace/reset、原请求重试、版本竞争 | get 无写入；修改有版本和去重；不改原记录        |
| R12  | 他人/已删/跨月装饰目标、未知素材             | 统一安全拒绝；不泄露他人存在信息                |
| R13  | 关闭装饰、素材失败、重复重置                 | 核心天气/回顾可用；不清空日记或偏好             |
| R14  | 多视图读取期间源版本变化                     | 不把不同来源声称为一致快照；重取或明确失败      |
| R15  | 月份快速切换、加载失败、NOT_IMPLEMENTED      | 旧月响应不覆盖新月；显示真实空态/错误，无假成功 |

客户端需要同账号会话代次和页面请求代次，记录保存/编辑/删除成功后使相关月份和窗口失效；已知更高 sourceRevision 后不接受较低版本。服务器查询如何保证来源版本匹配需与 Xiang Yu 评审，不靠客户端缓存替代服务端删除过滤。实际 V09 仍待接入验证。
