## 3. 一次 run 内的 17 项场景

| 编号                 | 核对重点                                                           |
| -------------------- | ------------------------------------------------------------------ |
| V01-commit           | 日记、账号元数据、无正文回执一起提交                               |
| V06-afterJournal     | 记录变更后注入故障，整笔事务回滚                                   |
| V06-afterReceipt     | 回执登记后注入故障，整笔事务回滚                                   |
| V02-journals         | 同 owner/date 唯一冲突被拒绝，另一日期的正向对照成功               |
| V02-receipts         | 同 owner/action/requestId 唯一冲突被拒绝，另一请求 ID 正向对照成功 |
| V03-create           | 同日两个新建竞争，仅一个成功且无静默覆盖                           |
| V03-edit             | 同版本两个编辑竞争，仅一个成功                                     |
| V03-edit-delete      | 同版本编辑与删除竞争，仅一个成功                                   |
| V04-same-input       | 同 ID 同输入并发只产生一次变更，另一次重放                         |
| V04-response-loss    | 提交后模拟响应丢失，再按原请求重试不增加版本                       |
| V05-different-input  | 同 ID 不同输入并发，第二输入不能重复写入                           |
| V05-rejection-replay | 已登记拒绝不能因后来状态改变而自动升级为成功                       |
| V07-boundary         | 固定时钟下 29/30 天、未来日期及跨日重试边界                        |
| V07-old-edit         | 窗口外已有旧记录可编辑，版本向前推进                               |
| V07-midnight         | 固定北京时间午夜前后新建边界                                       |
| V08-delete-recreate  | 删除态移除内容字段，重建版本前进，旧请求不复活内容                 |
| V08-empty-delete     | 空删除回执重放不能删除后来新建的记录                               |

单次 run 会按已部署逻辑执行上述全部场景；某一场景断言失败会记录失败并继续下一场景，最后汇总失败状态，不改断言掩盖结果。场景内部按锁定 SDK 配置允许最多 2 次事务冲突重试；报告另记录实际事务回调次数，不能把配置数写成实际重试成绩。

这些是 V01—V08 的基础能力实验。V09 回顾/装饰/迟到响应、V10 导出与链接/文件撤销、V11 正式账号隔离/停用竞争、V12 回执保留/密钥轮换/备份恢复仍待后续模块接入。固定合成时钟不是生产当前时间验收，模拟响应丢失不是实际网络断连实验；唯一冲突的精确 SDK 错误映射仍需 Xiang Yu 复核。
