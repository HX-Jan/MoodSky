### 2.2 页面逻辑与进程回执计时

页面逻辑耗时从读取Page源文件前开始，包含文件读取、VM编译与注册、onLoad、内存查询及同步setData。**脚本预加载的共用模块与D30夹具准备在计时区间外；Page执行时按需加载的依赖仍计入。** 终点为下表数据状态首次满足，后置正确性断言不计入该列。

| 页面     | 计时终点与校验                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------- |
| Today    | loaded=true、phase=idle；后置校验inputLocked=false、存在天气/保存处理器，且当天记录ID=synthetic_perf_30 |
| Universe | 月历与装饰均已setData，calendarBusy=false且无错误；后置校验当前月为2026-10，并有17个已记录日期          |

| 本地分组      | 执行条件                                                                                            | 样本数 |
| ------------- | --------------------------------------------------------------------------------------------------- | ------ |
| L-T-C / L-U-C | 分别测Today/Universe；每条使用新Node子进程，不预热该子进程；未清空操作系统文件缓存                  | 各5条  |
| L-T-W / L-U-W | 分别测Today/Universe；复用Node进程和已加载模块，每条重新建立D30与VM Page；各5次预热排除在正式样本外 | 各5条  |

正式样本按五轮交错执行，每轮顺序为L-T-C、L-T-W、L-U-C、L-U-W。“新进程/同进程”描述本地Node条件，不对应微信冷/热启动。

另对新进程组记录**进程回执耗时**：父进程启动子进程前至收到完整成功JSON。该值包含Node启动、模块导入、数据准备、页面运行、后置校验与回执传输，与页面逻辑耗时分别统计。

### 3.4 结果解释

本批次Today与Universe新进程组的页面逻辑中位耗时分别为7.718ms和4.965ms，同进程组分别为1.804ms和1.902ms。这些差异只描述本机、固定D30、离线替身和本次执行条件，不能外推手机启动、云数据库或长历史数据表现。

进程回执耗时还包含初始化与传输开销，不能与页面逻辑耗时混合计算。上述本地数据没有对应的已冻结验收阈值，因此不作性能达标或稳定性保证。

## 5 后续真机首屏测量

### 5.1 目标与采样条件

项目首屏目标为TTI≤2.5秒，仍属初步目标。约束针对每次启动还是某统计量、必要场景和允许波动，须在采样前由团队确认，不得看过结果后修改口径。

| 真机分组 | 设备与状态                    | 固定条件       | 计划次数 |
| -------- | ----------------------------- | -------------- | -------- |
| A-C      | 固定Android真机，客户端冷启动 | Wi-Fi、D30     | 5        |
| A-W      | 同一Android真机，客户端热启动 | 相同Wi-Fi、D30 | 5        |
| I-C      | 固定iOS真机，客户端冷启动     | 相同Wi-Fi、D30 | 5        |
| I-W      | 同一iOS真机，客户端热启动     | 相同Wi-Fi、D30 | 5        |

合计20次，每组5次，不足以作稳定P95或总体保证。本地L-T/L-U分组不计入这些真机样本。客户端冷启动须记录结束小程序实例的方法，退出聊天界面不一定等于结束实例；热启动记录离开时长和返回方式。无法确认时记未知，不强行归组。

云函数冷/热状态独立于客户端，只有平台标记或可靠实例证据才能确认，否则记未知；不以请求慢推定冷启动，不为制造冷启动改动正式环境。

### 5.2 计时与执行

1. 冻结测试版本、账号、网络和数据；登记设备型号/系统/微信版本、云部署/SDK、会话、电量/省电/温度/后台负载及录像帧率。D30由批准夹具建立，不绕过业务日期约束。
2. 按事前固定顺序准备各组；记录实际执行顺序、冷/热判定与云状态。预热请求独立标记，不纳入正式采样。
3. 用同一录像或同一计时来源记录T0为点击固定小程序入口，T1为今天页主要内容显示、阻挡加载层消失且主控件可响应；实际操作一次验证可交互。
4. TTI=T1−T0。已有会话的登录验证等待计入该场景；含人工首次授权的流程单列。启动图、骨架或静态按钮不算完成，最终错误且无法操作记启动失败。
5. 保留关键请求耗时、结果、脱敏requestId、失败原因和证据定位。开发工具和页面内计时用于诊断，不代替入口到交互的端到端指标；不相减不同设备/服务端时钟。
6. 按事先确认的观察上限结束未完成样本。建议15秒仅为组织上限；超时保留为“TTI大于上限”，不把上限当精确成功耗时。只有操作或取证错误可记测量无效，并保留理由、同条件补测。
7. 完成全部预定尝试，分组核对录像与T0/T1；有分歧时复核证据。失败、崩溃、超时及服务错误保留，不只取最快样本。

60fps单帧约16.7ms，30fps约33.3ms，报告精度须与取证方式一致。若加入页面探针，说明其版本和开销，对比批次采用相同实现。

### 5.3 原始记录与统计

每次记录唯一run_id/group_id、实际日期与时区、设备/版本、网络/D30条数、客户端与云启动证据、T0/T1/TTI、关键请求、成功/失败/超时/测量无效、录像路径及异常。没有实际采样时不填0秒或达标率。

- 成功耗时单独计算最小值、中位数、平均值、最大值，并列失败/超时数量。偶数样本中位数取中间两值平均。
- 达标率＝成功且TTI≤2.5秒次数÷有效启动尝试数；成功率＝成功次数÷有效启动尝试数。有效尝试中的失败和超时保留在分母。
- 明确无效的测量单列排除理由，应用崩溃、网络超时和服务错误不能据此排除。样本不足不报告稳定P95。
- 各组分别得出统计，不用混合平均代替分组结论。D0空态、DH长历史或移动网络专项按风险追加并单列；DH须事前确认记录条数和月份跨度，不混入D30基线。

### 5.4 慢样本诊断与复测

| 现象                   | 核查证据                                     |
| ---------------------- | -------------------------------------------- |
| 入口后长时间不出页面   | 平台启动、资源包和初始化阶段                 |
| 页面显示但不可操作     | 加载层、同步计算、主线程及渲染记录           |
| 等待关键接口           | 网络、重复请求、串行依赖和requestId时间线    |
| 首次云调用明显慢       | 平台冷启动标记及服务端执行信息               |
| 数据增加后变慢         | 相同环境下查询范围、分页、返回体和渲染量对比 |
| 热启动变慢或出现旧数据 | 生命周期重复请求、缓存失效与账号切换记录     |

缺陷保留版本、复现条件、预期指标、实际耗时、影响和证据；修复后另建批次，按相同设备/网络/数据/启动定义复测。修改公共启动逻辑时覆盖两类设备和冷/热状态。优化不得跳过身份校验、伪报保存、持久化未保存正文或显示上一账号缓存。

## 6 后续真人可用性方案

### 6.1 参与条件与统一规则

计划招募12名自愿参与的成年大学生，编号U01—U12。与第一周访谈分开登记活动和日期，人数去重；如曾见过原型，记录熟悉程度。正式私密试点须先通过核心权限与生命周期门槛；任务使用合成账号/记录及经核验或明确标识的地点资料，不收集真实私人经历。

测试前固定版本、任务卡、起始页、正确目标与滚动计步规则，准备重置账号及稳定设备。录屏需单独获得同意；不录屏时使用人工计时与笔记。主持人读统一说明，观察者不代操作。

操作任务从说明结束且起始页可操作时开始，到规定成功反馈时停止，加载等待计入；错误点击、返回、重试和滚动按统一规则计步。主持人提示方向或代操作后记“辅助完成”，不计独立成功。放弃、超时、系统故障及退出分别保留；是否补招和指标分母事前确定，不剔除失败者。建议观察上限为任务U01的120秒、U03/U04的180秒，开始前确认；它们不是验收目标。

### 6.2 四项任务与指标

#### U01 首次天气记录

- 需求与起始：UW3-F01/F02；今天页可操作，账号当日无记录。
- 任务卡：“请用这款小程序保存今天的一条天气记录。天气自行选择，文字和标签可选；如填写文字，请使用测试内容。”
- 成功标准：无方向提示完成一条合法保存、能识别保存结果，并由受控核查确认真实存在且无重复。完成率目标≥90%，按12人计至少11人独立成功；独立成功者中位耗时≤30秒，同时报告全部失败/超时。
- 观察：是否误以为正文必填、找不到保存、重复点击或不理解失败反馈。

#### U02 私人范围理解

- 需求与条件：UW3-F21及权限说明；所有人阅读相同版本，展示方式和时长一致。
- 问题：“根据页面说明，其他同学和普通资料运营人员能看到你的记录吗？你怎样理解这些记录的存储和处理？”
- 核心判定：明确其他学生、普通资料运营不可见，且未明确误以为自动公开、完全不离开设备或项目承诺端到端加密。未提及云服务术语不自动判错。
- 评分：先独立作答，保留原话或标明转述；满足全部条件记1，否则0。歧义仅用“请说说你这样理解的依据”中性追问，评分后再澄清。理解率目标≥90%，按12人计至少11人达标；两位评审有分歧时回看原回答并记依据。注销、导出理解另记，不临时加入核心评分。

#### U03 无定位查找地点

- 需求与起始：UW3-F11—F13；校园默认列表、定位未授权，已准备符合固定校区/条件且有效的目标地点。
- 任务卡：“在不授权定位的情况下，找到指定校区内符合给定条件的地点，并打开详情查看开放信息。”
- 成功标准：正确有效目标、未授权定位、无方向提示、3步内打开详情；三步内成功率目标≥80%，按12人计至少10人。超过3步找到目标记功能完成，但不满足3步目标。校区/条件依据正式核验资料事前固定，不编造可前往地址。
- 观察：强制定位、筛选理解、误选关闭/过期资料及开放信息是否可见。当前功能阻塞见4.3。

#### U04 指定月份记录查找

- 需求与起始：UW3-F08/F09；宇宙默认页，统一跨月合成记录、布局及目标，记录目标与当前月的距离。
- 任务卡：“请找到指定年、月中的目标日期记录，并打开详情。”
- 成功标准：无提示、3步内打开正确日期详情。逐人保留结果、步数和耗时；整体成功人数阈值由团队事前确认，不自行增加。
- 观察：年月入口是否可发现、空月是否混淆、卡片日期是否清晰，以及是否误认卡片公开。

### 6.3 后续记录要求

真实开展后逐人记录日期/自愿确认、设备/版本/熟悉度、任务及起始状态、同一来源的起止时间、完整操作序列/步数、独立或辅助完成/失败/超时/退出、私人范围回答/评分理由和证据定位。原始人数、失败案例及缺失数据同时报告，成功者耗时统计不能隐去失败者。小样本仅用于发现当前设计问题，不外推全体大学生的稳定比例。
