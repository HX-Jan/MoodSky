## 4. 如果误用的后果

| 误用方式                         | 直接后果                                                 | 可能引发的对接/接口失误                                  |
| -------------------------------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 把 N01—N06 当成非功能需求        | 隐私、性能、兼容性检查被错误归到任务 UI 编号，覆盖率虚高 | 测试报告无法对应真实质量属性；评审无法判断缺什么         |
| 自行补造 N07—N08                 | 出现没有需求来源的“正式编号”                             | 前后端可能为不存在的需求写接口、字段或测试，后续无法追溯 |
| 用 `needs.*` 命名接口            | 与现有 `tasks.*` 契约冲突                                | 前端 service、云函数注册表、权限门禁、测试全部要返工     |
| 把 N01—N06 当作每个 F 都必须关联 | 记录、回顾、导出等用例被强行挂到任务 UI 编号             | 需求追踪矩阵失真；缺陷归属和验收口径混乱                 |
| 把 N03—N06 直接写成新 action     | 与 Jiawei 的 tasks 契约草案重复                          | 重复实现、权限绕过、历史数据分裂                         |
