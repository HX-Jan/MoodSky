### 4.3 为什么不能把 N01—N06 当非功能需求

- 设计稿把 N01—N06 列在“此刻需求与可选小任务”章节，内容是 UI 入口和任务路径，不是隐私、性能、兼容性、可访问性等质量属性。
- 如果把它们硬当成非功能需求，测试报告会出现“N03 覆盖性能”之类的错误映射，后续评审无法判断真正的质量缺口。
- 隐私、性能、兼容性、可访问性检查应单独记录在 YL05、Qizhen Cai QT04 或后续性能/兼容性测试中，不使用 N 编号。

### 4.4 接口防守线

- 现有任务 action 只使用 `tasks.suggestions`、`tasks.quickChoice`、`tasks.transition`、`tasks.history`。
- 不新增 `needs.*`、`n01.*`—`n08.*` action；不在 payload 中增加 `n07`、`n08` 占位字段。
- 如未来确实需要新 action，必须在同一接口 PR 更新 `shared/contracts.js`、`docs/api.md`、调用方、权限门禁和测试，并由 Xiang Hong、Jiawei Fang、Qizhen Cai 复核。
