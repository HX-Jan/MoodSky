## 2. 模块接口字段复核确认记录

对照 w1-h04 逐字段复核（✔ = 与草稿一致；演示层已按该约定实现）：

| 模块             | 接口                            | 返回字段（演示实现）                                                                                         | 复核结果             |
| ---------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------- |
| 月历             | `review.calendar`               | `month`, `entries[]{id,date,weather}` 升序, `recordCount`, `sourceRevision`                                  | ✔ 不含正文/标签      |
| 月份列表（目录） | —（w1-h04 §3.4 已列为接口缺口） | 演示由 `review.calendar` 聚合出 月份+条数；空月样例 2026-08 单独列出                                         | ✔ 缺口登记，后端排期 |
| 月份档案         | `review.monthArchive`           | `month`, `cards[]{id,date,weather}` 降序, `recordCount`, `sourceRevision`, `cardTextPreview:false`           | ✔ 默认不返回正文     |
| 记录详情         | `journal.get`（H02）            | `entry{id,date,weather,tags[],text,version,createdAt,updatedAt}`                                             | ✔ 全文仅在此展示     |
| 天气分布         | `review.distribution`           | `startDate`, `endDate`, `windowDays`, `recordCount`, `sourceRevision`, `bins[]{weather,count}`（五类齐全）   | ✔                    |
| 时间线           | `review.timeline`               | 同上窗口字段 + `items[]{id,date,weather}` 降序 + `trendEligible`                                             | ✔                    |
| 装饰             | `review.decorations`            | get：`{month,version,stickers[]{stickerId,targetEntryId?},backgroundId}`；replace/reset 带版本控制与冲突处理 | ✔                    |

公共约定核对：`sourceRevision` 仅用于比较新旧、不是授权凭证；`entryId` 不可解析；空月返回空集而非错误码；`trendEligible` 只表示“达到 3 条数量门槛”，不等于输出趋势结论。

## 3. 三项核心规则（本周期对齐结论）

1. **正文内容默认不预览**：月历、月份列表、月份档案、分布、时间线一律不返回、不渲染正文。演示服务层在 `monthArchive` 的数据构造中物理上不含 `text` 字段（`tests/review-demo.test.js` 断言），详情页是唯一展示全文的位置。
2. **无记录状态的留白展示规范**：月历空日期只保留日期数字，无天气图标、无占位文字、不可点击；空月份显示空态文案（“本月暂无记录”）但网格仍按真实月份排布；档案空月不渲染任何卡片；分布空窗口五类计数为 0 并显示中性空态，不计算 0/0。**空日期不得被识别为阴天**——CLOUDY 只出现在有真实记录的日期（演示种子包含 2026-10-12 一条真实阴天记录用于区分）。
3. **本人详情页的展示逻辑**：按日期重新读取（`journal.get`）并核对链接携带的 `entryId`；一致才展示全文；记录已删除 → “这一天没有可展示的记录”；记录已重建（id 变化）→ “该日期的记录已更新，请返回刷新”，不展示旧卡内容（R06/R07）。
