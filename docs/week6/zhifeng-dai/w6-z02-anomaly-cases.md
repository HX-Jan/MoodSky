# W6-Z02｜异常测试用例集合

> 全部用例运行于禁云本地路径（`journalDemo = true`、`cloudEnabled = false`）+ 合成种子记录；
> F 组（多账号）使用仓库自带的合成后端与会话状态，因为在禁云路径下不存在真实账号。
> 「实测」列均来自 `node --test tests/week6-review-zhifeng.test.js` 的断言结果，不是人工观察。

## A. 非当前月份下拉刷新

| 编号 | 场景         | 操作                       | 预期                                                       | 实测                          | 结论 |
| ---- | ------------ | -------------------------- | ---------------------------------------------------------- | ----------------------------- | ---- |
| A1   | 非当前月刷新 | 打开 2026-09 → 下拉刷新    | 月份仍为 2026-09、2 条记录、指示器只停止 1 次              | 一致                          | 通过 |
| A2   | 连续两次下拉 | 不等待上一次结果再次下拉   | 复用同一读取 Promise，不重复请求、只停止 1 次              | `first === second`，停止 1 次 | 通过 |
| A3   | 空月份刷新   | 打开 2026-08 → 下拉刷新    | 月份保留、0 条、`本月暂无记录`、无错误                     | 一致                          | 通过 |
| A4   | 页面不可见   | `onHide` 后下拉            | 直接返回 `false`，不发起读取                               | 一致                          | 通过 |
| A5   | 刷新不跳月   | 在 2026-09 下拉            | 不得跳回当前月 2026-11                                     | `month` 仍 2026-09            | 通过 |
| A6   | 空月网格结构 | 打开 2026-08               | 6 周 × 7 = 42 格；31 个日期格 + 11 个留白、日期 1..31 连续 | 一致                          | 通过 |
| A7   | 返回页面     | 刷新后 `onHide` → `onShow` | 保留月份并重新读取，记录数不丢                             | 2 条                          | 通过 |

## C. 加载失败与自动重试

| 编号 | 场景               | 操作                                | 预期                                                                             | 实测 | 结论 |
| ---- | ------------------ | ----------------------------------- | -------------------------------------------------------------------------------- | ---- | ---- |
| C1   | 月历读取失败       | 首读抛 `NETWORK_ERROR`              | 显示「连接失败，请重新读取。」、月份仍为 2026-09、无卡片、`calendarBusy = false` | 一致 | 通过 |
| C2   | 返回页面自动重读   | 失败后 `onHide` → `onShow`          | 无需点击即恢复：错误清空、2 条记录                                               | 一致 | 通过 |
| C3   | 显式重试           | 连续 `onRetry` 两次（第一次仍失败） | 第一次返回 `false` 且保留错误；第二次恢复                                        | 一致 | 通过 |
| C4   | 失败后下拉刷新     | 失败状态下下拉两次                  | 第一次 `false` + 读取错误文案；第二次成功并清错                                  | 一致 | 通过 |
| C5   | 档案页读取失败     | 打开 2026-10 时抛错                 | 不渲染任何旧卡片（`month = ''`）、提示错误、`loading = false`                    | 一致 | 通过 |
| C6   | 档案页返回自动恢复 | 失败后 `onShow`                     | 恢复为 2026-10、5 张卡片                                                         | 一致 | 通过 |
| C7   | 错误文案不泄露底层 | 三类失败                            | 只出现固定中文文案，不含异常栈/SDK 错误码                                        | 一致 | 通过 |

| D8   | 降级下详情与档案可用 | 打开详情、月份档案                         | 详情 `ready` 且有正文；档案 5 条、无错误                                                                                 | 一致 | 通过 |

## E. 延迟旧请求（迟到响应）

前置：把演示服务的 `calendar(month)` 对指定月份挂起，形成「A 模块旧请求未完成」状态。

| 编号 | 场景                | 操作                                           | 预期                                                           | 实测                              | 结论   |
| ---- | ------------------- | ---------------------------------------------- | -------------------------------------------------------------- | --------------------------------- | ------ |
| E1   | 未完成时切换月份    | 10 月在途 → 切到 9 月 → 放行 10 月响应         | 视图保持 9 月 2 条；旧 10 月数据被丢弃，`month` 不被改回       | 一致                              | 通过   |
| E2   | 未完成时离开页面    | 10 月在途 → `onHide` → `onShow` → 放行旧空快照 | 返回后为最新 5 条；旧空快照（0 条）不得覆盖                    | 一致                              | 通过   |
| E3   | 未完成时切到 B 模块 | 9 月在途 → 打开档案模块 → 放行旧响应           | 档案模块月份/计数不变、不出现 9 月记录；B 模块无 A 数据        | 一致                              | 通过   |
| E4   | 返回后视图正确      | 从 B 返回月历                                  | 月份为 2026-09、2 条记录                                       | 一致                              | 通过   |
| E5   | 缺陷复现（修复前）  | 读取在途时离开页面，返回                       | 修复前 `calendarBusy` 卡住导致 `onShow` 跳过重读，旧空快照写回 | 已复现并修复（见 README 第 5 节） | 已修复 |
| E6   | 丢弃判定            | 任意旧响应晚到                                 | 通过请求令牌（`_requestSeq`）判定，不依赖时间顺序              | 一致                              | 通过   |
