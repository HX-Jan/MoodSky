# 成员提交、补交与评审步骤

适用原12名成员和两周各60项任务。范围按[模块分工](../team.md)、[W1计划](../week1/first-week-detailed-plan.md)、[W2计划](../week2/second-week-detailed-plan.md)，不因补交重新分配职责。

## 1. 先查原交付，避免重复合并

在[成员索引](README.md)查原PR、实际接收PR与材料。#3经#5、#39—#41经#42收录；#11当时为空，正文后来由#51补交；#18旧布局未全部采用。关闭的PR先查去向，不重新合并旧快照。最新源码以main为准，不以旧标签或旧截图覆盖当前七天气。

已有Issue继续引用。新功能用“功能任务”，补交用“成员交付与补交”表单；写周次、任务号、本人、协作/复核人和环境。资料接收使用`Refs #编号`，不要填`Closes`提前关闭完整业务议题。

## 2. 从最新main开分支

下面用于有主仓库写权限的成员。Fork成员从`upstream/main`同步，向自己的`origin`推送；详见[开发步骤](../development.md)。先处理未提交修改，不强推main，不整包覆盖队友目录。

```sh
git fetch origin
git switch main
git merge --ff-only origin/main
git switch -c docs/w2-jh-handoff
```

一个分支对应一项清晰交付，如`feature/w2-jh-campus`、`fix/w2-qc-session`、`docs/w1-yf-supplement`。已有成员目录保留原名称，不为统一大小写搬动证据；首次新建目录使用小写英文短横线。

## 3. 写清实际结果

每项记录：原任务周和编号、实际提交日期、基线完整SHA、路径、预期/实际、环境、复现步骤、脱敏证据、缺口和接收人。跨周补交不追认按时完成。原稿、原作者与整合人后续修正分别登记。

本地/合成、SDK离线、微信模拟器、真实云端、手机用户确认和指定设备独立验收分列；子集和历史结果不重复相加。截图标注版本、日期和运行模式。资料PR只能证明文件接收，不能代替入口/调用链验证。

工时、估点由本人回填；共享成果说明包含关系。独立意见由实际复核人填写。访谈需真实采集依据、参与/使用许可和匿名去重；模板、前期示例或定性访谈不能冒充新参与者和操作型可用性样本。原始失败、旧截图和私人证据边界保留，不补造成功或个人签字。

## 4. 检查并提交

```sh
npm run cloud:prepare
npm run check
git diff --check
git status --short
```

逐项检查暂存范围；排除个人配置、node_modules、真实私人数据、密钥和临时二维码。接口、数据、导航变化同时更新约定、调用方和关键行为验证，与对应负责人共同复核。

```sh
git add docs/week2/junhan-huang
git diff --cached --stat
git commit -m "docs(w2-jh): supplement JH01-JH05 handoff"
git push -u origin docs/w2-jh-handoff
```

这里的`docs/week2/junhan-huang`是尚缺独立交接的新目录示例，其他成员用自己的现有目录。提交为`type(scope): 具体行为`，使用`feat`、`fix`、`docs`、`test`、`chore`等；scope体现模块或周次成员，不只写“update”“最终版”。

## 5. 创建、复核与合并PR

目标`HX-Jan/MoodSky:main`，标题例如`docs(w2-jh): 补交 JH01—JH05 校园后台交接`。填写模板中的周次、任务号、原交审与当前SHA、来源、正常/异常验证、未完成项和整合记录。

用`documentation`、`bug`、`enhancement`等类别加`week1`/`week2`标明归属；整合PR加`integration`。里程碑只作交付归档，不把“已关闭比例”当作120项任务的验收完成率。

普通成员由HX-Jan审批；拥有者自己的PR沿用既有豁免。所有人仍须满足最新main、quality、讨论解决、squash线性历史与禁止强推规则。先看原交审和后续新增提交，再看最终diff，不能把整合修正误计为原成员贡献。

合并后核对main提交并更新[原台账](README.md#120项任务与固定来源)。被替代PR记录接收PR和未采用内容，不将“关闭”改说成“已直接合并”。原始提交、作者与讨论不为追溯形式而改写。

## 常见问题

| 现象                         | 处理                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| PR为Closed而非Merged         | 在[历史PR表](pull-requests.md)查接收去向，从当前main补交，不重合旧分支 |
| CI通过但页面/云端不可用      | 核对入口、候选开关、默认门禁和实际环境证据，CI不是业务验收             |
| main无法快进或分支过旧       | 查清本地额外提交和未提交修改，合并最新main解决冲突，不强推             |
| 缺报告、估点或独立意见       | 标待本人回传/待指定复核，不代填，继续其他可独立工作                    |
| 旧报告写五天气、未部署或失败 | 保留原时点，查后续来源，不据旧报告回退源码或抹掉失败                   |

云部署、实验写入、索引/权限、数据清理与公开发布继续按既有固定授权范围处理；Issue、标签、里程碑和本规范不构成这些操作的授权。
