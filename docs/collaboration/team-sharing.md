最小本地同步流程如下。Fork成员将团队远端命名为upstream，并向自己的origin提交；不要为了同步覆盖未提交改动。

```sh
git clone https://github.com/HX-Jan/MoodSky.git
cd MoodSky
npm ci
npm run setup
npm ci --prefix cloudfunctions/moodsky
npm run check
```

这些步骤不部署、不写真实数据库。需要看内存演示时，按开发说明在本人的忽略配置中设置`cloudEnabled:false`及`journalDemo:true`；不要把个人配置、凭据或真实记录提交GitHub。

新增快速联调：安装根依赖后运行`npm run team:check`，不需要云SDK安装、个人配置或微信/腾讯云权限。它实际执行9组内存调用链，详见[使用与本地调用样例](../../tools/team-integration/README.md)；通过不代表组员云权限已获准。

## 路径一：微信开发者工具

1. 组员用**自己的微信号**登录微信开发者工具，导入当前仓库根目录，确认项目AppID是上述团队AppID。测试号、另一个个人AppID和团队项目不是同一权限范围。
2. 由小程序管理员在微信公众平台的成员管理入口核对该微信号的项目成员/开发者资格；体验者资格不能作为开发者资格的证明。具体菜单以当前后台为准，此处没有读取或代改成员名单。
3. 在该项目进入“云开发”，选择上述既有环境。记录“找不到环境”还是“看得到环境但某个操作被拒绝”。若界面要求创建新环境，先返回核对AppID/登录账号，不用个人新环境替代团队环境。
4. 由管理员在云开发控制台的设置/权限相关页面核对该成员可执行的资源操作。开发者工具访问资格、资源查看/部署权限分开检查；本轮未打开该面板核实菜单或授权。先满足资源查看需要，部署或数据操作按实际分工决定，不为排错直接给所有成员全权管理员。
5. 变更成员授权后，让该组员重新进入控制台并验证能否看到环境及三个函数；没有必要先删除项目、清缓存或重建资源。若仍失败，保留原错误与操作时间。

腾讯云[小程序控制台说明](https://cloud.tencent.com/document/product/876/46905)指向微信维护的控制台；历史[云开发团队权限说明](https://developer.cloud.tencent.com/article/1739488)描述过设置/权限入口，但不是本轮当前面板的现场验证。**项目成员资格和云开发操作权限均须在实际后台确认。**

## 路径二：腾讯云网页或命令行

1. 核对当前登录的腾讯云账号是否是团队环境归属账号，或该账号下已授权的CAM子用户/协作者。组员用自己的独立个人腾讯云账号登录，只看到个人环境，并不证明团队环境不存在。
2. 从团队环境基本信息确认真实地域，再选择控制台/CLI地域。当前还没有可靠地域值；环境名和ID后缀不能替代地域证据。
3. 管理员核对目标账号、目标环境、资源及操作范围。查看环境列表、读取函数元数据、部署、调用函数、读写数据库是不同操作；不能只授予调用能力就推定可进控制台。腾讯云[权限管理概述](https://cloud.tencent.com/document/product/876/47055)说明CAM用户授权；[环境级访问控制](https://docs.cloudbase.net/cam/access-manage)还明确管理SDK策略与控制台/云API权限并非同一范围。
4. 需要子用户访问时，由归属账号管理员配置目标环境的必要权限。接收账号、真实地域及所需操作尚未核实前，不复制全权策略，不把管理员密钥共享给组员或AI。
5. CLI核对当前登录方式、账号及显式环境/地域；只提交脱敏的工具版本、目标环境、操作名称和错误码。访问密钥、Token、二维码凭据和完整函数配置不要粘贴到聊天或仓库。

[CloudBase账号FAQ](https://docs.cloudbase.net/faq/account)说明微信开发者工具云控制台使用小程序绑定的腾讯云账号；账号一致性是必要核对点。本文不要求重新关联、转移或新建环境，也没有替换组员腾讯云登录态。

## 能访问环境后，还要区分哪一层拒绝

| 现象                                                    | 优先排查                                    | 本项目的处理                                                                           |
| ------------------------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------- |
| 导入项目/打开IDE即拒绝                                  | 微信登录号、AppID、项目开发者资格           | 由管理员核对成员；不是修改业务代码就能解决                                             |
| 环境列表没有团队ID                                      | 入口账号归属、AppID、真实地域、环境可见权限 | 分别走上面的微信或腾讯云路径                                                           |
| 看得到环境，但列函数/部署失败                           | 目标账号及具体操作授权                      | 查看与部署分别验证；不拿部署当权限探针                                                 |
| 平台PERMISSION_DENIED或类似平台码                       | 先判断来自管理控制台、函数调用还是数据库SDK | 核对对应层授权，不直接放开所有资源                                                     |
| 数据库直接读取被拒（例如-502003）                       | 是否绕过服务端直接查集合                    | 当前客户端集合默认拒绝读写，是项目既有策略；改走已核验云action，不为协作改成全员可读写 |
| ApiResult返回NOT_IMPLEMENTED                            | 默认入口尚未组装业务候选                    | 不代表平台登录失败，给更多管理员权限也不会自动实现业务                                 |
| ApiResult返回UNAUTHENTICATED/ACCOUNT_DISABLED/FORBIDDEN | 内部账号状态或运营角色门禁                  | 云资源管理权限不能代替内部业务身份；真实Web映射尤其仍待接入                            |
| INVALID_REQUEST/INVALID_INPUT                           | API版本、requestId、action、payload及注入层 | 按当前契约与错误说明改调用，避免用旧版示例                                             |

## 建议的组内协作安排

全员共享GitHub main、契约和本地测试；组员提交PR，统一审查后合入。普通前端/设计/验收工作先用本地合成与既有体验包，不要求每人都能部署团队云。需要真实云联调的后端成员再逐个验证资源访问范围，正式函数由明确负责人统一部署，避免互相覆盖。学生/运营的业务身份另走服务端门禁，不能与开发者授权混用。

排障完成的检查点必须是**同一位组员、同一个账号、同一台机器**：确认团队AppID→看到团队环境→列出三个函数→所需操作获准。业务调用按固定测试范围另验；本机成功、看得到函数或CI通过均不能代填组员结果。
