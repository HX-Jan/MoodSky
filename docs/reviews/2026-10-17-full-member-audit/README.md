## 3. 文件覆盖及复查方法

- 最终 12 个 PR 共 **555 条文件记录、536 个不同路径**；其中对本轮开始前的本地提交比较为 489 条一致、61 条改动、5 条缺失。5 条缺失全部属于 #11 的空文档。这些是逐 PR 条数，同一路径在不同 PR 中会重复出现，不是功能完成数量。
- 再把原交审快照的文件并入，得到 **558 条记录、538 个不同路径**。额外发现的原稿范围是 #7 的 `shared/constants.js`、`shared/validation.js` 及 #14 的 Me 样式。它们在最终 PR diff 中已消失，仍单独说明为何不采用。
- [逐文件取舍表](file-decisions.csv)保留原 blob、最终 PR blob、合并/远端/当前工作区差异和理由；[完整来源表](sources.json)固定 SHA。工作区 blob 包含本轮本地修正，HEAD 字段是上一轮视觉接入基线，不能把两者混淆。
- 用 `git diff <原交审SHA> <最终head> -- <路径>` 复看审查中取舍，用 `git diff <原交审SHA> <目标版本> -- <路径>` 复看后续整合；不能只看 Squash 合并是否成功。文件表引用的 GitHub 来源和 git 对象可复现，原 API 响应与完整差异另留本机测试目录。
- 对成员原交审测试文件提取测试名称，与当前文件逐项比较，**没有消失的原测试名称**。这只是覆盖追踪；测试是否有力仍依赖用例与实际入口，不能用名称存在代替运行结果。
- 55 项设计条目逐项对照 [design-coverage.csv](design-coverage.csv)，区分已接视觉/本地流程、部分采用、提案和真实业务未实现。没有声称逐个人工查看 13,248 个设计节点或独立复验每一条历史日志；生成素材/历史证据通过文件对照保留，关键原图、实际页面、模块与跨页行为人工复查。
