## 服务器配置和剩余接入边界

三个文件不再在导入时加载或初始化 wx-server-sdk。没有给默认 router 注册新的业务处理器；默认部署包的隔离测试也拒绝引入这三个工厂。它们是内部接入能力，不能把合并说成真实账号/导出/注销已经上线。

- 注入的 db 必须使用 `database({throwOnNotFound:false})` 并提供 SDK 事务；未传入 db 或能力时不会自行连接真实云环境。
- `createRepository` 的 `accountUniqueIndexReady:true` 是部署前待核对的服务器条件，不能从请求传入，也不是程序已验证云端索引的证明。缺少此条件仍可查已有账号，但不新建。记录写入额外要求已有 journalRepository、回执策略及原 requestId；delete 必须传 expectedVersion，不能静默忽略竞争。
- `createExportService` 必须显式提供 maxRecords（每集合输入上限）和 `readSourceState(ownerId, tx)`。后者必须在传入的事务内读取可信账号源栅栏，返回 ownerId/status/epoch 及 journals、favorites、tasks、preferences、decorations 五领域非负版本；相关写入者必须在其事务中单调推进。程序会另行读取账号真实状态，但不能认证一个错误实现的源版本适配器。没有适配时不生成貌似一致的快照。此内部结果与 tools/export-candidate 的格式器字段对齐，仍需正式消费者复核。
- 清理参数为 `cleanupByOwnerId(collection, ownerId, {jobId,batchSize})` 或 `executeAccountCleanup(ownerId,{jobId,batchSize})`。持久 cleanup_jobs 必须匹配归属，状态为 pending/processing，并有 `exportAccessRevoked:true`。该字段及新增标记元数据是服务器 worker 候选协议，尚未修改共享数据字典或部署清单；布尔值不代替真实撤销动作和独立验收。没有真实撤销证明的任务不能进入清理。
- 清理记录的集合固定为七类本人业务数据，不允许清 accounts、角色或删除账本。标记只保存 ownerId/collection/docId/jobId/时刻/阶段，不复制正文或文件引用。账号始终保持 disabled，完成前再次确认七个范围均为空；零条进度来自实际空查询，不能给未处理的导出任务硬写 0。
- 云文件删除由注入的 removeExportFile 返回 deleted 或 alreadyMissing 回执。它必须真正执行幂等删除；程序不会用本地 true 替代平台操作，也不会把回调失败当作成功。完整生成、受控下载及撤销机制仍未完成。
- `deterministic-days-v1` 日期代际布局的 journals 清理保持 NOT_IMPLEMENTED，避免物理删除其版本墓碑后回到 v1。旧随机 ID 布局的清理改进不能冒充该布局的恢复协议已通过。正式字段/索引、独立账本备份和恢复仍待原负责人共同确认。
