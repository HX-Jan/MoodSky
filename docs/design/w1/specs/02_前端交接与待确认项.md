# Moodsky 校园情绪天气｜前端交接与待确认项

版本：W1 v0.2；日期：2026-10-14。交付状态为**可编辑设计及按画面演示状态的可点击原型，待页面负责人和前端评审**。原型导航与组合状态不等于真实登录、数据库、定位、导出、删除或注销服务；没有执行真实数据操作。

## 1. 文件与页面对应

`design/design.json` 是设计源；`design/tokens.json`、`design/tokens.css` 是颜色与尺寸映射；`design/screen-index.json` 记录最新画面 ID。`screens/<画面ID>.svg` 供单页导入，`figma-import/` 提供恢复原生文字、框架、组件和连线的导入工具；按其中 README 操作。浏览器入口为 `preview/index.html`；各状态可从画面选择器进入。

| 产品页面 / 流程  | 画面 ID 与主路径                                                                              | 前端实现关注点                                                                |
| ---------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 首次使用与 Today | welcome → today → selected-partly → saved；其他天气对应 selected-* → saved-*；选填支路 record | 登录与隐私摘要；天气选择；无正文保存；同日编辑                                |
| 校园地点         | campus → filters → campus-filtered → place；campus-map、place-second、place-closed 为分支     | 标签筛选、列表/地图、开放状态、收藏；定位可拒绝                               |
| 指定月份回顾     | universe → months → universe-sep → detail-sep；卡片支路 universe-cards / universe-sep-cards   | 年月状态、日期绑定原记录、私人范围、等价文字列表                              |
| 我的与偏好       | me → preferences / preferences-off → me                                                       | 装饰、减少动态、写作提示分别控制；原型演示组合状态                            |
| 数据导出         | me → privacy → export-options → export-pending → export-ready → download-info                 | 创建异步任务、刷新状态、本人鉴权、有效期；export-failed / export-expired 支路 |
| 注销             | privacy → delete-account → account-confirmed → account-verify → account-pending               | 二次确认、会话复核、会话撤销、删除任务可查询                                  |
| 可选任务         | today → needs → tasks → task-water / task-sky / task-walk → task-done                         | 用户自报完成，换一个、task-alternative、rest 可随时选择                       |
| 编辑与删除       | detail → edit；detail → delete-confirm → deleted → universe-deleted                           | 更新原记录，同步卡片/月历/统计；取消删除无改动                                |
| 后台低保真       | admin-home → admin-edit；admin-home → admin-jobs                                              | 地点/任务字段、导出删除任务状态、角色与权限边界                               |

更多详情和状态以最新 screen-index 为准。原型中的月历与记录是示例集合；实现时每个日期及卡片必须绑定同一条实际记录，不能复用示例路由作为业务逻辑。月份空态也必须保留用户选择的实际年份与月份。

## 2. 四条主路径的预期验收

| 路径             | 评审时需复核的预期结果                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 首次私人保存     | 用户看懂范围并自主登录；只选天气即可保存；成功后出现私人卡；同一天修改不新增记录；退出未保存状态有说明；保存不会触发公开投稿或气象贡献。               |
| 地点筛选与详情   | 拒绝定位仍可按室内、安静等条件找到地点；详情包含开放时段、注意事项、无障碍及核验日期；关闭地点不被当作可前往推荐；导航需用户主动触发。                 |
| 指定月份查看记录 | 从宇宙入口经选择月份、点日期打开该月记录；卡片视图有日期与中文天气名称；未记录日期留白；删除后月历、卡片及统计一致，重新打开不恢复旧数据。             |
| 偏好、导出与注销 | 每项偏好独立控制，关闭装饰不影响核心操作；导出与注销入口能找到；异步任务有明确状态；链接过期可重新发起；失败不显示完成；注销前能先导出并理解删除影响。 |

以上是**待验证的验收标准**，不代表前端已通过评审，也不代表实际用户达到完成率或耗时目标。

## 3. 必须保持的数据与权限边界

私人记录和宇宙仅本人界面可见，服务端仍有必要受控处理；不能宣传端到端加密或平台绝对无法关联账号。记录保存、公共投稿、校园气象贡献是独立动作；首轮原型不开放树洞或真实校园气象数据。以后贡献天气时只提交天气类别，不携带正文、标签或精确位置，并要求独立确认和撤回入口。

首次登录不默认获取头像、昵称、手机号或定位；地点推荐不从私人日记推断需求。后台维护地点和任务，查看必要的任务状态，不能显示私人正文、微信身份或个人天气轨迹。日志与错误上报同样不得记录这些内容。

源方案 §7.3“天气宇宙页”错误混入公开树洞输入线框；本轮依据 FR-04 与 §20–22，将 Universe 定义为私人月份回顾。树洞作为后续单独立项内容，不放入首轮 Tab。

## 4. 异常与实现边界

| 状态 / 画面                                     | 实现要求                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------- |
| save-error / unsaved                            | 明确尚未保存；保留当前输入；允许重试与继续编辑，必要时主动复制自存。       |
| conflict / session-expired                      | 版本冲突避免静默覆盖；登录过期要求重新验证，恢复输入机制需与会话边界核对。 |
| universe-empty / year-empty                     | 中性说明、不催补签；少于 3 条不输出趋势判断。                              |
| location-permission / campus-map / place-closed | 权限拒绝与地图失败不阻断列表；关闭、施工和核验状态可见。                   |
| export-pending / ready / failed / expired       | 接口状态驱动；下载入口仅本人可访问；有效期以实际任务返回值展示。           |
| account-pending / admin-jobs                    | 区分提交成功、执行中、失败和清除完成；任务凭证不包含私人正文。             |

补记最近 30 天是方案中明确的**补记范围**，不能据此推断历史记录不能编辑；历史编辑范围由产品与前后端共同确认。设计状态页不应替代服务端授权与版本校验。

## 6. v0.2 天气数据与新增交互

预设天气新增 `HEAVY_RAIN`（暴雨）、`TYPHOON`（台风）；自定义使用 `CUSTOM`。现有五种编码保留，不把新增类型插入心理评分或诊断序列。前后端、校验、存储和导出枚举均需一起更新；不能只更改图标。

`design.json` 的 `weatherOptions` 提供名称、编码、配对说明和颜色；`customWeather` 提供1–10码点校验、图标/配色清单、默认样例及内存状态边界。

| 字段提案              | 内容与规则                                            |
| --------------------- | ----------------------------------------------------- |
| weatherType           | 原五种 + HEAVY_RAIN + TYPHOON + CUSTOM                |
| customWeather.name    | CUSTOM时必填；trim后1–10 Unicode码点                  |
| customWeather.icon    | sunny / cloudy / rainy / typhoon / custom，固定白名单 |
| customWeather.color   | 6种已定义底色，固定白名单                             |
| customWeather.version | 可选素材版本，确保后续能还原图标                      |

正式存储应将自定义组合保存在每条记录中，保留日期与原记录ID；导出包含当时名称、图标和颜色。新增天气的选择→保存→详情→编辑→月份回顾已补充设计快照，指定月份返回十月会保留该天气示例；历史编辑切换天气保留原日期。浏览器自定义输入和取消可实际操作，私人正文、账号与服务器任务仍未实现。

浏览器中的自定义编辑是一次本地原型状态，刷新会清除；并不证明多记录持久化、跨设备、并发更新或导出已实现。Figma原生图层及连线导入仍需在实际客户端复核。
