## 二、为什么不能按当前证据提审

1. **没有“同一候选”。** 计划要求周二从干净提交生成 1.0.0 候选，并在同一包上完成 iOS、Android 和目标云回归。当前仓库没有 1.0.0 版本、标签、Release 或封包清单；本机候选是 `28f810c` 的 `0.4.0`，不是 1.0.0。Yifan 的记录基于 `9f58ed8`，Qinghan 的校园记录基于本地预览包，Zhifeng/Qizhen Chen 为本地/模拟器；这些不能拼成“同一候选通过”。
2. **P0 真机证据不足。** W5-R01 只有 Yifan 的 iPhone 自报，缺第二真实账号和跨业务日，且非同一候选；W5-R02/R03 只有本地或合成测试；W5-R04 未领取真实文件；W5-R05 没有 A/B、停用和真实注销。按决策规则，P0 缺少真实证据不能提审。
3. **P1 校园打卡已出现真实失败。** Qinghan 在 Xiaomi 14 Ultra 和开发者工具中均看到“接口不存在”；目标云部署包只支持 `campus.checkin`/`campus.checkinHistory`，当前客户端使用 `campus.checkIn`/`campus.checkins`。这不是 UI 文案问题，而是客户端与目标云契约不一致。若不收起入口或重部署并对齐，提审后用户无法打卡/读取本人状态。
4. **P1 普通任务范围未收敛。** 正式模板、状态规则和目标云 `expectedDate` 未共同确认；#166 的默认 `closed` 与入口修复仍开放，未进入 `28f810c` 候选。当前候选在可信云条件下可能仍显示任务入口，存在“假完成态/无响应按钮/未确认写入”风险。
5. **候选包未完成发布链。** 本机候选的 `uploaded`、`deployed`、`cloudLifecycleVerified`、`phoneVerified`、`submittedForReview`、`publicRelease` 全为 `false`；没有目标云健康响应、构建指纹、回退演练或平台回执。
6. **独立结论缺失。** 蔡奇真的隐私/生命周期独立验收、洪翔的版本与发布决定、各模块负责人的真机回填均未取得。Yuen 不能代签，也不能用本地 1489 项通过替代真实环境。
