## 4. A/B 切号（同日不同账号）

- A 账号：`2026-10-17`，CUSTOM「A合成私有」，正文 `A private body`。
- B 账号：同日 `2026-10-17`，SUNNY，正文 `B private body`。
- 切换前四页面均显示 A 的记录；执行 `state.accept(B)` 后：
  - 月历、月份档案、回顾、详情同时清空，并提示“登录状态已变化”；
  - 四页面 JSON 中不存在 A 的名称或正文；
  - 刷新后月历/档案/回顾只显示 B 的 ID 与日期；
  - A 的详情链接在 B 下进入 `stale`，即使 B 在同一天有记录也不展示 B 的正文；
  - 切回 A 后四页面恢复 A 的记录，B 正文不出现。

## 5. 数据层一致性（Z05）

同一 3 条记录集合（`10-01`、`10-08`、`10-18`）在四个数据源中的 `id/date/weather/weatherName` 完全一致：

- `review.calendar`：3 条，升序 `10-01, 10-08, 10-18`，`recordCount=3`；
- `review.monthArchive`：3 条，倒序 `10-18, 10-08, 10-01`，`recordCount=3`，`cardTextPreview=false`；
- `review.timeline`（30 天）：3 条，倒序；`recordCount=3`；
- `journal.get`：逐条与上述集合一致，正文存在；
- 三条读取结果的 `sourceRevision` 相同；
- 月历、档案、时间线载荷中均不含正文。

结论：同一快照下四类读取结果一致，未发现同步偏差。
