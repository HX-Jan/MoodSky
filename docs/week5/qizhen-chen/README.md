## 入口与状态对照

能力规则集中在 [capabilities.js](../../../miniprogram/modules/system/capabilities.js)，页面为 [tasks](../../../miniprogram/pages/tasks/index.js)。生产配置必须满足可信云条件，且显式选择有效模式；未知模式按关闭处理。

| 模式                        | 记录页“需要一点帮助” | 我的任务历史       | 任务直达链接                            | 实际请求与按钮                                                                    |
| --------------------------- | -------------------- | ------------------ | --------------------------------------- | --------------------------------------------------------------------------------- |
| `closed`（生产默认）        | 仅校园地点           | 隐藏               | 显示暂未开放，可返回校园                | 不创建任务会话、outbox、任务读取或写入                                            |
| `readOnly`                  | 可打开任务建议       | 隐藏               | 历史参数降为建议                        | 仅公开建议及快捷推荐；不读取私人历史，不显示选择/完成按钮；服务响应不能提升此模式 |
| `enabled`，游客             | 可打开任务建议       | 经现有登录流程进入 | 浏览公开建议，主动登录返回原任务/历史页 | 不自动登录；登录前无私人任务读写                                                  |
| `enabled`，有效本人会话     | 可打开               | 可打开             | 本人建议或历史                          | 按服务契约显示选择、完成、替换、跳过；写入需准确回执                              |
| 任意模式，朋友圈场景 `1154` | 静态单页             | 不展示私人内容     | 保持静态                                | 不发任务/会话请求，不执行交互处理器                                               |

关闭及只读是本次**客户端构建范围**，不会撤销后端权限，也不能影响旧客户端。发布人仍需结合目标云验证关闭后的后端访问、旧客户端兼容和历史数据可读性。原有持久请求不会因换成关闭/只读包被删除或发送；恢复时需核对原账号、环境、函数和原版本，使用获准的开放范围显式重试，不修改请求日期。

## 页面修复与既有契约

- 删除重复的空建议说明和自指任务快捷按钮；读取失败不会显示“还没有任务记录”。仅成功读取空历史才展示空态，保留分页失败重试。
- 只读建议显示“建议”，隐藏私人历史和操作按钮；只读约束同时覆盖云控制器和本地演示处理器。关闭页面有可用的校园返回按钮。
- 未确认提交显示“正在提交”或“结果尚未确认”，阻止连点与新操作。网络未知结果保留原请求，实际卸载重开后也不自动重放；“重试原操作”才发送原 `requestId/payload/expectedDate`。
- 只有回执的任务 ID、目标状态和日期均匹配才显示成功。明确拒绝、未实现、跨日冲突和未知结果分别提示；明确未开放的操作转只读，不伪装写入成功。
- 保留隐藏页面、切号、停用、迟到响应和本机存储失败的既有防护；游客进入任务页沿用主动微信登录，登录后返回原页面。

本次按现有 [接口约定](../../api.md) 和 [任务控制器](../../../miniprogram/modules/tasks/cloud.js) 检查：`available` 可选择；`selected` 可完成、替换或跳过；`completed/replaced/skipped` 不再提供新状态按钮。历史只读本人，最近 90 天，使用既有分页协议。此处是实现对照，不能替代 Jiawei 对正式模板、状态表和目标云版本的确认。

## 构建与复现

[生产打包器](../../../scripts/package-production.js) 将同一 `taskMode` 写入客户端配置和 `manifest.json`。命令行 `npm run release:package -- /绝对路径/新目录` 默认关闭普通任务。负责人确认只读或开放后，可在仓库根目录使用已有导出 API 明确构建，例如：

```js
const { buildProduction } = require('./scripts/package-production');
buildProduction({ outputRoot: '/absolute/new-candidate', taskMode: 'readOnly' });
```

合法值为 `closed/readOnly/enabled`，无效值会在创建输出目录前拒绝。禁止只手改打包后的配置：范围变更必须重新出包并核对 manifest 和文件指纹。构建不会部署云函数或上传微信；当前版本不是已冻结的 1.0.0。

模拟器使用 [可复现驱动](../../../tools/week5-qc/wechat-task-entry.cjs)，依赖本机安装的 `miniprogram-automator` 及官方开发者工具自动化端口。先 `npm run setup`，确保本机配置 `cloudEnabled:false`，再用开发者工具 CLI 的 `auto --project <仓库绝对路径> --auto-port 9420 --trust-project` 开启自动化。设置 `MINIPROGRAM_AUTOMATOR_MODULE` 为已安装模块路径、`QC_SIMULATOR_OUTPUT` 为证据目录后运行驱动。驱动只替换内存配置和服务，使用合成任务；结束恢复禁云配置，清理自身合成会话和 outbox，并回到记录页。
