# 真实设备文件送达补验步骤（初稿）

状态：初稿（C2）。C3 结合 Xiang Yu 的领取回执形成完整 `device-delivery-checklist.md`。本文件所有步骤本地均未执行，执行前不得填通过。

## 前提条件

- 一台 Windows 或 macOS 电脑版微信，已登录本人微信，能打开小程序。
- 一台 iOS 或 Android 真机，已登录另一微信账号（用于接收文件），微信版本支持 `shareFileMessage`。
- 小程序处于正式/体验构建，账号可正常登录且导出任务可申请（目标云已部署对应版本）。
- 测试用账号内仅放合成内容（如「同步测试」一条记录），不使用真实私人日记。

## 步骤一：电脑保存（saveFileToDisk）

1. 真机或电脑登录账号与数据页，申请 JSON 导出，等待状态「可领取」。
2. 电脑端微信打开同一小程序，进入账号与数据页，点击保存导出。
3. 核对：弹出系统「另存为」对话框；保存后提示「文件已保存到电脑。」。
4. 打开保存的文件：JSON 可解析、字段与 c1 的 share-entry-map 排除项一致（无账号标识、无他人数据）。
5. 记录：文件名、大小、保存路径截图（脱敏）、提示截图。

## 步骤二：手机发送到聊天（shareFileMessage）

1. 真机登录同一账号，申请 JSON 导出至「可领取」，点击保存导出。
2. 核对：调起微信发送面板；选择文件传输助手发送成功后提示「文件已发送。」。
3. 在文件传输助手打开该文件：能打开、格式为 JSON、内容为本人导出。
4. 记录：发送面板截图（脱敏）、接收侧打开截图、提示截图。

## 步骤三：Markdown 格式与兼容文本

1. 申请 Markdown 导出，重复步骤二；核对文件为 .md 且可识别。
2. 若真机拒收 .md，走兼容文本分支：核对发送的是 MoodSky.md.txt 且内容与原文件一致。
3. 记录：格式辨识截图、兼容副本文件名与打开结果。

## 步骤四：取消与失败分支（真机）

1. 发送面板中选择取消：核对提示「已取消发送，可重新领取文件。」且导出仍可重试。
2. 让接收端不可用或断网触发失败：核对中文失败反馈与可重试入口。
3. 记录：取消与失败的提示截图。

## 步骤五：退出与切号后的真机核对

1. 手机上打开导出预览后退出登录：核对预览清空、返回游客态。
2. 用第二台真实微信账号登录：核对看不到第一台的预览、文件与任务。
