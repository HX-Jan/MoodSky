## 工具选择与分层

- Node.js 自带 test/assert/VM：加载真实 Page 与真实控制器，精确挂起响应和比对完整重试输入。新增 4 个回归分别覆盖选择、完成、替换、跳过的丢回执；`npm test` 自动收录。
- 当前 `createProductionEntry` + 既有 native SDK 离线数据库：执行鉴权/任务服务/回执逻辑，统计真实合成历史行数；与手写固定响应相比，可以检查替换的两行状态与幂等回放。夹具禁止真实 HTTP，合成身份不出证据。
- 官方微信开发者工具 + 本机 automator：检查实际渲染控件、页面切 tab、校园与记录保存返回、历史显示；测量两处右侧按钮。无需新的项目依赖，也不把模拟手机当真机。
- ESLint/Prettier/类型/结构/文档与全量行为检查：作为仓库质量门禁；测试数量只描述覆盖，不能代替其他成员的独立验收。

## 用例与结果的解释

[24 行模式表](evidence/mode-action-state.csv)是三种模式下四动作和各自动作后历史的对照。它们复用同一当前业务逻辑，不作为新增 24 项单测计数。[4 组未知结果](evidence/local-results.json)则是新行为回归：服务已经提交但响应丢失时，页面应保留“不确定”，而不是自行推断完成或另造请求。

实际结果表明，select/complete/skip 的历史始终一行，replace 两行；重试完整复用原输入，不增加行数。页面已选状态在校园返回或心情保存返回后不自动变为完成。原生截图显示替换/跳过的终态以及当前右侧布局，见[截图与矩阵](README.md)。

## 反例与测试局限

本轮没有发现新的产品缺陷。为确认迟到导航测试有检测能力，只在 VM 字符串中移除访问序号守卫，再执行相同步骤：旧访问自动导航 1 次；原源码 0 次。这个变异没有写入产品文件，也不是新 bug 修复提交。W6 原失败与修复按原日期、原 SHA 引用。
