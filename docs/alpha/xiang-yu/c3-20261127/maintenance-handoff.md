# C3-XY 维护与恢复交接单

本单交给运维/复核人，说明哪些结论只能在真实环境成立、如何在真实环境补验，以及出错时的恢复边界。本目录的本地结果只覆盖内存库 + 生产业务入口，**不能**替代本单。

## 1. 真实环境补验清单

| 编号 | 补验项                 | 真实环境条件                                           | 预期结果                                                                   | 失败时如何判定                                        |
| ---- | ---------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------- | ----------------------------------------------------- |
| M1   | 定时触发器执行到期维护 | 部署后的云函数定时器，等待一个自然周期                 | `ready` 且已过 `expiresAt` 的任务转 `expired`，正文移除，`fileId` 为 null  | 触发器未执行或报错；任务仍 ready 且可领取正文即为失败 |
| M2   | 自然到期（无人工触发） | 真实等待 `exportFileHours`（24h）                      | 到期时刻起领取返回 `CONFLICT`「导出尚未完成或已失效，请重新读取。」        | 到期后仍能领取正文                                    |
| M3   | 云端分批清理           | 真实数据库 + 清理 worker，一次性触发到底               | 每批 ≤10 行/集合，进度单调递增，最终 `completed`，进度总数等于账号业务行数 | 单批超过上限、进度回退、完成后仍残留业务行            |
| M4   | 多实例并发             | 两个实例同时 step 同一 jobId                           | 只有一方推进，另一方拿到已完成/等待态，不重复计数                          | 进度重复累加或行被重复删除报错                        |
| M5   | 外部文件协议           | 仅当导出文件迁到对象存储时适用                         | 当前实现正文在库内（`export_jobs.content`），无外部文件；如迁移需另立契约  | 本项当前标注“不适用”                                  |
| M6   | 设备送达               | 真机保存/分享导出文件                                  | 领取后文件可打开、格式与 `extension` 一致，失败有可辨识提示                | 文件损坏、格式不符或静默失败                          |
| M7   | 备份残留               | 数据库备份与恢复演练                                   | 备份中的已注销数据属于残留，需在恢复流程中过滤或重新清理                   | 恢复后已注销账号可登录或导出可领取                    |
| M8   | 恢复验证               | 用备份恢复后执行一次全量清理                           | 墓碑仍在、业务行清空、B 与公共数据完整                                     | 恢复出可用的已注销账号                                |
| M9   | 300 秒领取凭证         | `planClaim` / `authorizeRead` 接入生产领取路径后       | 凭证过期、跨账号、改源后均拒绝                                             | 凭证过期仍可领取，或凭证可跨账号使用                  |
| G1   | 新代数账号清理         | 账号注销后重新注册（`registrationGeneration+1`）再注销 | 墓碑保留 `registrationGeneration`，新账号数据按自身范围清理                | 旧代数清理误删新账号数据，或新代数墓碑丢失路由字段    |

## 2. 补验步骤（建议顺序）

1. 部署当前主干，确认定时器与清理 worker 均已启用。
2. 用合成账号 A/B 走一遍申请 → 领取 → 注销 → 清理，记录每批 `state` 与 `progress`；与本目录 `cleanup-batches.csv` 对照结构，不要求行数相同。
3. 用真实时钟等待一次自然到期（M2），再触发一次维护（M1），确认幂等（第二次返回 0）。
4. 并发触发清理（M4），确认进度不重复。
5. 真机领取并打开文件（M6）。
6. 备份恢复演练（M7/M8），确认已注销数据不会复活。
7. 若已接入领取凭证，补 M9；否则保持“未接入”的边界说明。

## 3. 恢复边界

- **到期 ≠ 删除**：到期只移除正文与哈希，保留任务元数据；领取被拒但行仍在，直到账号注销后的分批清理。
- **清理不可逆**：已删除的业务行无法从业务入口恢复；唯一恢复手段是数据库备份回滚。
- **备份回滚是隐私事件**：回滚会复活已注销账号的数据。若必须回滚，回滚后应立即对相关账号重跑清理，并在事件记录中注明回滚范围与再次清理的回执 jobId。
- **墓碑是拒绝凭证，不是恢复入口**：`accounts` 墓碑保留 `openid`、`status=disabled`、`identityKind`、`journalLayout`、`closedAt`（新代数账号还保留 `registrationGeneration`），用于拒绝登录与导出，不能据此恢复数据。
- **公共集合不可清理**：`places`、`task_templates` 不参与分批清理；任何“清理后地点消失”的情况都应按缺陷处理。
- **凭证不可重放**：注销回执一次性绑定 jobId；回执泄露等于清理进度可被他人读取，应按凭证泄露处置（作废回执、重建清理任务需产品确认）。

## 4. 失败处置

| 现象                             | 处置                                                                      |
| -------------------------------- | ------------------------------------------------------------------------- |
| 维护任务报错、ready 不转 expired | 停止继续领取，手工触发一次维护并核对 `expiresAt`；仍失败则回滚该版本      |
| 清理进度停滞或回退               | 暂停 worker，检查 `cleanup_jobs.progress` 与集合行数，必要时按 jobId 重建 |
| 清理误删 B 或公共数据            | 立即停止 worker，从备份恢复受影响集合，按隐私事件上报                     |
| 恢复后已注销账号可登录           | 视为严重缺陷，冻结导出入口，重跑清理并核对墓碑字段                        |
