# 小程序隐私与内容安全开发规则

适用对象：MoodSky / 校园心情记事本的所有开发者、评审者、发布者及参与开发的 AI。维护日期：2026-11-05。

本文件规定团队必须执行的开发与发布约束，用于降低隐私接口停用、审核退回及违规处置风险，不保证平台审核通过或免于封禁。它不替代微信后台的隐私指引、UGC声明或实际运营措施。

## 2. 信息与功能边界

以下是当前开发边界，不是允许今后任意收集这些类别的授权。每类信息仍需具体用途、最小字段、访问规则和适用的告知或授权。

| 信息或能力   | 当前处理边界                                                             | 变更时必须核对                                                                            |
| ------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| 心情记录     | 主动填写的天气、自定义名称、标签、正文及日期，只供本人记录、回顾和管理   | 新增字段、可见范围、搜索、导出、删除和内容审核；私密不等于可免除平台要求                  |
| 微信身份     | 服务端根据可信微信身份关联账号，业务表使用派生账号标识                   | 派生标识仍按个人信息保护，不称为完全匿名；不得依赖客户端提供的ownerId/OpenID授权          |
| 头像昵称     | 可选、自主设置，用于个人中心；不能因拒绝设置而禁止无关功能               | 仅在实际开放版本声明；头像选择不等于获得整个相册或摄像头的权限                            |
| 必要操作记录 | 仅保留防重复提交、原请求重试、导出及注销清理核验所需记录                 | 列明字段和保留规则，不擅自加入全量点击跟踪、行为画像、营销统计或SDK自动追踪               |
| 手动校园打卡 | 记录用户主动选择的地点和完成时间，不代表设备定位或已经核验到场           | 地点选择记录也与用户关联，应补入数据范围、UGC适用场景、本人导出和注销清理；开放前同步声明 |
| 月历         | 根据日期及本人记录生成页面，不写手机系统日历                             | 不因页面有“日历”而申请系统日历写入；新增`addPhoneCalendar`或重复日程等能力需重新评审      |
| 数据导出     | 本人校验后生成导出结果，准备完成后领取期24小时；用户可主动保存或发送副本 | 领取到期与后台物理清理分开验证；用户自行发送文件不等于系统可自动公开私人记录              |

手机号、通讯录、身份证、位置/GPS、系统日历写入、相册写入、通用图片/视频/文件选择、录音、摄像头、剪切板、运动、蓝牙及传感器不在当前开放边界内。不得为“备用”或绕过报错批量勾选、调用。未来确需新增时走第3节流程，不把本表当永久禁用清单。

不能将“文件导出”误报为“读取用户选中的文件”，也不能将“月历回顾”误报为“写入系统日历”。后台权限名称和接口对应关系以发布时官方文档及实际检测结果核对。

## 3. 每项变更先写清信息影响

新增或改变字段、权限、SDK、外部请求、用途、可见范围、日志或留存方式时，PR必须填写下表。无影响也写明理由及核对范围，不只填“无”。第三方依赖升级需检查默认采集和上报行为是否变化。

| 必填项     | 填写内容                                                              |
| ---------- | --------------------------------------------------------------------- |
| 功能与入口 | 用户操作、实际接口/组件、客户端和后端文件                             |
| 信息与用途 | 字段、来源、必要性、可见范围、是否涉及敏感信息                        |
| 流向与存储 | 接收服务、SDK/插件及版本、存储位置、可访问主体                        |
| 授权与拒绝 | 何时告知、如何同意/拒绝/撤回、拒绝后的行为                            |
| 生命周期   | 保存期限或确定标准、到期处理、导出、注销、备份和日志处理              |
| 平台与验证 | 隐私/UGC/类目等更新项、负责人、生效证据、拒绝/失败/隔离测试和未完成项 |

先确认功能必要性和适用规则，再实现最小范围采集；在对真实用户开放前，使实际行为、产品提示、后台隐私指引、UGC声明和补充文档一致。平台审核未通过、更新未生效、必要授权未实现时，不得发布受影响功能。可继续开发默认关闭的候选并明确阻塞项。

扩大原有用途、方式或信息种类时，不能复用旧同意自动放行；按适用规则及已声明的小程序内弹窗方式重新告知和取得同意。不得先上传再补同意。不得将私人日记发往AI、广告、统计、推荐或外部分析服务来实现原声明外的用途。

## 4. 授权、访问与分享

- 微信隐私接口/组件只在已声明、满足平台隐私授权要求且用户触发相应功能时使用。优先沿用微信官方支持的授权流程；自行开发弹窗时必须正确完成平台要求的同意同步。
- 普通登录按钮点击、浏览页面、打开隐私指引或勾选自制复选框，不自动等于完成所有隐私授权。操作系统权限和隐私指引同意分别处理；不以删除授权检查、降低基础库或伪造同意绕过限制。
- 拒绝、取消、微信版本不支持、接口失败时给出可理解的反馈，不循环强制弹窗，不上传相应数据；保持无关公开浏览功能可用，不伪造成功。
- 所有私人业务由服务端校验当前身份、归属及账号状态；禁止客户端直接读写私人集合、公开下载私人导出、跨账号缓存或旧响应泄露数据。
- 日记正文、身份、会话、导出凭证不得进入分享标题、卡片、二维码、路由参数、公开页面、遥测或错误日志。正常页面分享由接收者读取自己的数据；本人主动导出的文件另明确提示内容范围。
- 隐私指引、联系渠道、数据管理入口保持可访问；不能把更正、删除、撤回等用户请求全部等同为“必须注销”。当前未提供的请求入口由公布的联系渠道受理，并如实说明处理方式。

## 5. 保存、导出与注销

- “必要的最短时间”不能解释为永久保存或无需制定规则。每个数据集合、回执、任务、日志及备份必须有目的、期限或确定标准、清理责任和验证依据；未明确的事项记录为发布前待办，不编造天数或定时删除承诺。
- 保留24小时导出领取校验和过期正文清理。领取失效、定时任务执行、物理清理及用户手机副本分别说明和验证；不得把领取期填成所有日记的保存期。
- 注销经服务器确认后停止私人访问并撤销导出领取，后台按任务清理。不得声称按钮点击即在所有数据库、日志和备份中瞬时彻底删除。
- 必要停用标记及清理元数据仅服务于停用、清理核验和防止恢复，不含日记正文、不用于营销。记录具体字段及保留必要性，定期复核，不宣称这些标记是完全匿名或所有数据均已删除。
- 新增集合、图片存储、任务或SDK数据时，同时检查本人导出、删除、注销清理和备份恢复；恢复前保留停用围栏，不让旧备份重新激活注销账号。未完成的生命周期不得用文档或测试通过掩盖。

## 6. UGC与内容安全

- 允许用户产生文本、用户资料、图片、视频或音频时，如实更新UGC场景。私人可见与对外公开分别说明，不能因为“不公开”就虚报“不包含UGC”。
- 内容安全机制填写实际实施情况。没有调用检测API、没有接入审核产品、没有人工流程和执行证据时，只能如实记录未审核，不能勾选已经审核。
- 当前发现的内容安全缺口必须作为相关版本发布前的核对项：按届时平台要求确认适用的检测和处置机制；若平台要求检测，先实现、验证并更新声明，再提审/开放。选择“未做内容审核”并不保证可过审，也不自动补齐审核能力。
- 接入内容安全API须在服务端保护凭证，核对文本/图片覆盖、场景参数、接口权限及数据处理说明。测试违规结果、调用超时、失败、待复核和重试；需要审核的内容未通过时不对外发布，不遇错直接放行。
- 不得为“人工审核”而默认赋予成员浏览全部私人日记的权限。必要访问限制人员、目的、字段并留审计；公开投诉、违规处理与私人内容权利请求分别建立实际流程。
- 新增公开帖子、评论、陌生人互动、公开头像资料或用户照片传播时，必须重新评审可见范围、内容安全、举报处置、服务类目及适用资质；不能靠现有私人记事本声明直接开放。

## 7. SDK、日志和敏感信息

- 新增SDK/插件/服务前检查提供方、版本、隐私规则、真实传输字段、自动初始化/采集行为和关闭方式；按实际情况更新SDK清单或云服务处理说明。服务端工具包与手机端SDK分别核对，不能因“腾讯官方”而跳过评审，也不能不加区分全部填成客户端SDK。
- 当前原生云调用、服务端依赖与云端存储不等于已接入所有第三方SDK，也不等于没有外部服务处理信息。构建工具和UI库若不处理用户数据，不虚报其采集范围。
- 日志只留排错或处理核验必需字段；禁止输出真实正文、原始OpenID、手机号、头像原图、令牌、密钥和完整请求/响应。测试夹具使用合成数据，证据脱敏后才可进入GitHub。
- 不从日记推断医疗诊断、心理风险标签或营销画像。新增敏感信息处理、未满14周岁用户场景或其他特殊用途时，先核对必要性、专门保护和适用同意要求，不凭“校园用户”推断用户均成年。

## 8. PR与发布核对

每个PR按[PR模板](../.github/pull_request_template.md)填写信息影响和剩余事项。纯文档或默认关闭候选可合入，不因此将后台配置、授权或内容审核标为完成；本地检查通过只证明其覆盖范围。

发布者在受影响版本提审/对外开放前逐项留存以下脱敏记录，缺项就暂停相应功能发布并列待办：

1. 固定客户端构建、后端版本、配置和实际启用功能，逐项核对数据字段、接口、SDK及存储流向。
2. 核对正式隐私指引、补充文件、联系人、UGC声明和适用类目，记录平台状态、日期及证据位置。编辑完成、提交成功、审核通过、生效和公开发布分别记录。
3. 在实际目标环境验证首次使用、同意、拒绝、撤回/变更用途、取消及异常路径；只在适用场景调用权限，不携带私人内容分享。
4. 验证身份隔离、导出到期及失败、注销后拒绝访问、新增数据清理、必要停用标记保留和审核处置路径。使用合成或专门授权账号，不擅自操作真实用户数据。
5. 已收到平台整改通知时核对站内信和期限；异常权限、泄露或声明偏差先收敛受影响入口，保留最小脱敏证据并交负责人处理，不通过新增权限或虚假声明绕过。

文档、PR模板及CI不代替公众平台配置、内容安全实现、真实设备检查或运营响应。本次仅增加开发规则，不执行微信上传、云部署或真实用户数据处理。
