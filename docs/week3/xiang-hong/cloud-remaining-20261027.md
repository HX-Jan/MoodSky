## 本轮已实现

- `tools/week3-validation/`增加一次性协议：prepare、四个独立worker、read、inspect。没有业务任意调用、清理或更改运行批次的入口。
- 两个worker竞争同一天的首次创建；另两个竞争记录写入和账号停用。通过既有账号共同写围栏及原生SDK有限重试执行，保留最终业务结果及事务回调数。
- 固定生成90天合成历史，实际候选读取器检查7/30/90天数量、记录ID、日期及来源修订，并检查正文、私人标签和身份不进入时间线。历史数据是测试夹具直接构造，**不是90次真实用户保存或90天自然留存证明**。
- 停用成功后验证原写入请求重放、记录读取和月历均拒绝；停用失败时read阶段拒绝，不会补写记录。
- 保留部分准备、调用未知和失败报告。重复prepare、worker或read拒绝再次写入；只读inspect可查原批次。已存在同批次孤立数据也不能被准备过程覆盖。
- 复用的数据库适配器增加服务端固定scope及集合白名单；旧工具默认scope不变。正式业务代码、前端及七天气均未改动。
- 打包器生成三个部署文件及外置四份调用脚本；导入、打包和本地测试均不会连接云端。脚本不重试未知写结果，workers脚本在任一调用完成前就发出四个请求。

## 获准后执行步骤

1. 核对当前时间、AppID/环境、三个候选文件哈希及原函数版本。确认本轮单次授权包含临时部署、固定批次写入和恢复。旧批次/旧日期授权不沿用。
2. 调用开发者工具部署候选 `candidate/moodsky-h03-probe`，等待用户在原生弹窗确认。保存任务ID；确认前不主动轮询、不重发部署。
3. 在本次专用 `readonly-console/client` 项目执行外置 `calls/inspect.js`，应为not-started；如果已有该批次则只查明原状态，不重跑。项目默认关闭正式云业务，无启动自动调用。
4. 显式执行 `calls/prepare.js`一次，需返回ready/90天。失败或超时先只读inspect；preparing不能重发prepare。
5. 执行 `calls/workers.js`一次，同时发出四个独立 `wx.cloud.callFunction`。每个worker自己的云调用结果单独保存。仅发送四个，不用“多跑几次”制造冲突。
6. 只读inspect，确认四个worker均completed且stopPassed为true，才执行 `calls/read.js`一次。即使createPassed失败也保留结果；read完成不意味着整体通过。若worker状态未知或停用失败，保留批次并转恢复。
7. 最终inspect保存原始返回与脱敏报告。`state: unknown`不等于服务器未执行；只查询原批次，不重发worker/read，不替换请求ID或批次。
8. 无论验证成功或失败，恢复 `rollback/moodsky-h03-probe`，用户确认恢复部署弹窗后检查任务结果与Active状态，再下载恢复后的根三文件核对回滚哈希。恢复失败保持明确未关闭状态，不宣称已恢复；拒绝/超时不自动重发。

受控调用脚本通过开发者工具 `automation_evaluate --fn-source` 执行；PowerShell先用 `Get-Content -Raw`读入已固定脚本再作为一个参数传入，不用拼接包含身份或密钥的命令。`calls/inspect.js`只读；另外三份即使名称为read也包含报告/围栏事务写入，均需本次授权。这些脚本不能在正式体验版里自动启动。
