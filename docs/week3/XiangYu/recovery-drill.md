# W3XY05 删除账本恢复边界演练记录

> 维护者收件说明（2026-10-28）：下文为成员原交审的本地演练自报，未附可执行脚本或原始运行日志，尚未独立复现，不证明仓库已有自动恢复重放执行器。本文仅规范排版；逐字原文见[原稿](recovery-drill.original.txt)，来源与剩余条件见[PR #74整合记录](../../reviews/2026-10-28-pr74-integration.md)。

- 任务：验证灾难恢复（备份还原）时，`deletion_markers` 能否阻止已删除数据复活。

## 1. 演练环境与前置条件

- 运行环境：本地 Node.js + Mock 数据库（合成副本）。
- 重放机制：系统在恢复数据后，会遍历 `deletion_markers` 集合，将账本中标记为 `completed` 的文档从主库中强制物理删除。

## 2. 演练输入与步骤

### 2.1 模拟初始状态

- 账号 A（状态 `disabled`）。
- 主库中包含 3 条记录（journals: j1, j2, j3）。
- 账本中存在 1 条已完成删除标记（`deletion_markers`：journal j2，状态 `completed`）。

### 2.2 执行模拟恢复重放

1. 模拟平台备份恢复，将主库和账本全量还原到某个时间点（此时 j2 还在主库中）。
2. 触发恢复后重放程序。
3. 重放程序扫描 `deletion_markers`，发现 j2 处于 `completed` 状态。
4. 重放程序将 j2 从主库中再次删除（或确保其不可见）。

## 3. 校验结果

- [x] j1（未被标记删除）正常可见。
- [x] j2（在账本中标记为 completed）恢复后仍被成功清理，**未复活**。
- [x] 账号 A 仍保持 `disabled` 状态，不会因恢复而自动重新激活。

## 4. 剩余条件与风险

- 本次为本地合成数据演练，不代表云端真实备份库的物理特性。
- 真实平台的备份保留期（如 30 天）与重放脚本的执行时效，需要在真实接入后再次验证。
