# H02/H04 原生数据库候选接入

2026-10-23。H03 修复版真实隔离实验已 17/17 通过（[原始报告](h03-symbolic-cloud-20261023.json)），但原 W2 组装仍使用 WX 数据库封装，存在相同的错误类型丢失路径。因此新增 `tools/journal-storage/native-database.js`，并给 `createWeek2Backend` 增加服务器显式参数 `nativeDb`，将修复接回记录与回顾的实际候选链路。

## 用法与边界

调用方提供由锁定 @cloudbase/node-sdk 3.17.2 的公开 `init(...).database()` 构造的实例：

```js
const backend = createWeek2Backend({ nativeDb, receiptPolicy, now });
```

也可继续传既有 `db`；两者同时传入会拒绝。客户端 payload 无法选择实例、环境、集合或开关。模块本身不初始化 SDK、不加载凭证、不连接网络。将来接入正式包时调用方需明确直接锁定原生 SDK，不能依赖未声明的传递依赖；本次没有改变正式云函数依赖或业务入口。

适配保留原生返回的 code，在事务提交前抛出固定消息和原类别，供 SDK 自身识别明确冲突；不解析原始消息、不把 -501001 当冲突、不增加外层重试。校对 data、账号 add 返回 ID、文档空读、更新 stats、查询排序/投影、serverDate 等 WX 形状，沿用已有账号、确定日键、版本、回执和导出围栏。

仅允许候选所需 accounts/journals/request_receipts/deletion_markers/month_decorations/task_templates 六个集合，不提供通用删除/清库入口。账号 active、明确布局及计数器检查仍执行；新账号初始化仍需 accountUniqueIndexReady 与显式布局，既有账号不迁移。配置布尔值不代表真实唯一索引已验收。

## 已执行验证

新增 9 项真实锁定 SDK 的离线集成检查，合成传输以外不替换数据库封装；HTTP/HTTPS 独立阻断：

- 同一个账号围栏符号冲突注入：WX 原路径回调一次后 INTERNAL_ERROR；nativeDb 路径按 SDK 重试后保存一次、来源版本只加一。
- CUSTOM 名称、私人正文/标签、跨月读取、原请求重放、编辑移除旧名称、删除刷新和重建新 ID。
- SYS_ERR、未知符号及纯数字 -501001 不重试/不确认成功；随后复用原请求可恢复，不生成另一条记录。
- 新账号仅显式开启时创建一次；原账号不变，停用和旧布局门禁保持。
- 可选公开任务查询保留排序、上限、字段白名单，不解析私人账号；其他集合调用在发请求前拒绝。

当前完整 **593 项本地测试通过**（573 基线 + 11 探针边界 + 9 本候选）。新候选未用于真实业务集合、没有新增真机结果；H03 的 17 项是单独的探针实验，不能与 593 相加或作为本候选正式上线证明。正式接入、真实账号/索引/迁移决策及成员独立验收仍需补齐。
