## 已定位缺陷

原 services/journal.js 在版本/窗口拒绝时直接从事务抛 AppError，事务回滚导致拒绝没有绑定请求 ID。因此被拒 ID 可换输入成功，竞争失败请求也可能在删除后变成重建。

修复前新增五项测试四失败、一通过，覆盖删除后重用、改输入、跨午夜和过期后再执行。修复后五项全部通过。这不是历史五项云端失败的根因结论。

现在拒绝保存 state:rejected、固定 code、当时代际和 HMAC/时间；touchAccount 与回执一起提交，提交后才抛业务错误，不含正文/天气/标签/payload。非法输入、身份失败、平台失败及未知提交不记成已确认拒绝。原输入未过期则重放原拒绝，不因后续代际变化升级成功；异输入/过期拒绝重用，成功回执的原有代际校验保留。

## 负优化检查

可靠拒绝绑定需要写入元数据。在 16 路 SDK 合成竞争中观察到 1 次创建、3 次拒绝确认、12 次 SDK 预算耗尽。后者如实为 INTERNAL_ERROR，不冒充冲突。随后逐个复用原请求，15 位败者都取得 CONFLICT，日记版本和导出版本只推进一次。

这不是吞吐提升的证据；真实环境需要测重试率/时延。没有增加无限重试、扩大 SDK 预算或凭数字错误自动重试。完整回归与正式包检查用于确认其他路径不受影响。
