## 首次账号创建到记录保存

此前账号创建仅写 active 和时间字段，创建后仍缺少记录存储布局，第一条记录返回 NOT_IMPLEMENTED。现在给服务器构造函数增加可选 `newAccountJournalLayout:'deterministic-days-v1'`，在**新账号的同一次 add**中初始化 journalRevision、operationFence、exportEpoch 为0。

```javascript
const { createWeek2Backend } = require('./tools/week2-integration/backend');
const router = createWeek2Backend({
  db: serverDatabase,
  accountUniqueIndexReady: true,
  newAccountJournalLayout: 'deterministic-days-v1',
  receiptPolicy: serverReceiptPolicy,
});
```

上例为服务器组装示意，参数不是客户端输入。只有实际验证过唯一索引和布局方案后才能配置相应开关，布尔值不是检查器。默认仍不创建账号/启用记录布局，正式 index.js 未接入。没有部署、更改数据库设计、索引或云数据。

已有 active/disabled 账号直接返回原状态，不补字段、不重置计数器、不复活停用账号。旧随机 ID 记录迁移仍未实现。如果其他旧创建入口先创建了无布局账号，本入口也不擅自升级；该账号继续保持未启用状态。格式未知的布局在服务器构造时拒绝。

9项新增测试覆盖首次创建→保存→回顾→原请求重放、默认/唯一索引门禁、旧账号不变、16路首次竞争、创建失败以及SDK序列化。锁定 SDK 离线传输也验证了 insertDocument 格式、唯一键碰撞后的重读及“插入已提交但响应丢失”恢复；合成唯一索引不替代真实 CloudBase 约束证据。

## 离线演示删除重试与后端保持一致

原内存演示不会删除重建后的内容，控制器也会在旧成功回执后重读新记录；它的行为和当前后端候选的 CONFLICT 规则不同。本轮为演示删除回执记下代际，日期重建后再提交旧删除请求明确报 CONFLICT，页面等待用户点击重新读取；有未保存草稿才确认放弃，没有草稿不增加确认弹层。

正常保存、编辑和确认删除不增加步骤。只有“删除已提交但响应未知，期间另一调用方重建，再重试旧请求”的路径改为显式冲突恢复；该路径多一次主动重读，是与后端一致的取舍，不声称原实现会实际误删数据。旧空删除也不能在后来新建后继续返回未变化的成功。

补两项演示服务回归，并更新既有删除代际和控制器用例。首次完整回归暴露一条仍期待旧成功语义的测试；另一次断言错误地要求无草稿时也弹确认。两次失败日志均保留，最终分别验证有草稿确认放弃、无草稿直接重读，不为迁就测试改变控制器行为，也没有仅删除失败断言。模拟器启动首次自动化挂接超时后恢复；测试驱动同样修正了无草稿确认的假设，原始中间结果保留。
