## 导出任务的来源版本与创建保持原子性

PR #31 的可选导出模块原先先用事务读取来源版本，再另开事务创建任务。两次事务之间来源变化，或建任务事务被 SDK 重试时，会沿用先前的版本，产生刚创建便失效的 pending 任务；原受控读取策略会拒绝旧版本，所以不能据此宣称已发生私人文件泄漏。

现在在创建任务的同一事务内检查账号、调用来源版本读取器及写任务。SDK 重跑事务回调时也重读版本，不再关闭在旧快照上。正常首次创建少一次事务；任务 ID、响应投影、旧请求遇来源变化报 CONFLICT、格式白名单均不变。来源读取器必须使用传入的事务；其他四类来源的可靠计数器仍需各模块共同接入，不能传固定0就称已具备正式导出。

新增4项检查，先复现两条旧版本失败，再验证单事务、SDK 竞争重试、旧请求不覆盖原任务、新请求使用新版本，以及来源/提交失败不留任务。相关19项通过，属于本地合成和锁定 SDK 离线验证，没有实际生成或下载云文件。

## 编辑页离开后隐藏正文并保留草稿

记录编辑页原先没有 onHide 处理。现在离开时清空传给界面的正文、记录、标签、天气选择及确认信息，并禁止隐藏页的迟到响应重新渲染；控制器仍在本次页面内存中保留草稿和原请求。返回后，未保存草稿、emoji、标签及未知结果的重试状态会恢复；干净表单重新读取。正常保存/删除不增加操作步骤。

同时修正删除请求延迟完成时无条件返回上一页的问题：只有当前编辑页仍可见时才执行自动返回，避免用户已经进入别页后被迟到回调误弹回。隐藏时已完成的删除在返回编辑页时重新读取，用户可正常返回。这是该特殊路径的行为变化。

这不保证系统后台任务缩略图/截屏已被平台清除，也不提供进程重启后的草稿持久化。账号失效仍按原控制器规则清空草稿；没有把私人正文写入 Storage。

新增4项页面回归，覆盖隐藏/恢复、迟到读取、未知保存原请求重试及延迟删除。微信开发者工具实际窗口另完成18项检查和3张截图逐张复核：使用明确标注的内存合成数据，正常保存、重试、重建代际及可见状态删除返回均通过。自动化第一次连接超时，窗口就绪后重试成功；不计为业务通过或业务失败。

## 离线演示的请求绑定与种子完整性

## 回顾事件校验、旧读取取消及离线详情隐藏

回顾内存数据源原来把没有 entry 的事件也当作删除，不论其kind是否为failed或缺失；直接确认删除/较新修改后，也没有取消此前已在等待读取的旧同步，迟到结果可恢复旧卡片。现只接受真实日期及明确saved/deleted，saved必须是完整有效记录；种子和新增记录拒绝重复日期/ID并移除未约定字段。无效事件不修改数据、版本或通知，也不取消正在进行的合法读取。

直接确认的变更会取消同日期旧读取；确认删除即使日期已经为空也会使旧读取失效，不让其重新放回记录。仅有date/kind的失效通知应走syncFromJournal重新读取，不能用缺entry代表删除。该方法在设置读取令牌前先检查service.get/日期/kind。构造或传入不完整演示数据不再被默认为可用；已有正向测试夹具补齐真实必需字段，缺字段负向断言保留。

离线详情页现在与云模式同样在离开时清空正文/标签并丢弃迟到响应，回来才读当前值；隐藏期间的刷新事件不重新绘制正文。补充本地演示标签，修正“只有详情展示全文”的不准确说明，因为私人编辑页也展示输入；卡片默认隐藏正文的规则保持不变。这只清空页面渲染层，不承诺平台后台缩略图或系统内存清除。

## 未知操作重试的门禁与环境绑定

真实控制器的本地复现：保存已提交但响应丢失后，下一次重试若报CLOUD_NOT_CONFIGURED/NOT_IMPLEMENTED/FORBIDDEN，原逻辑会清除pending并开放新输入，甚至提示“本次尚未保存”，无法说明第一次的真实结果。现记录本次页面内的未知历史；这些后续门禁保留原请求和草稿、锁定编辑并明确提醒“此前操作结果仍未确认”。首次直接遇到同一门禁仍保留可编辑草稿，不凭空制造待确认请求。确认成功/冲突、身份失效清空和明确放弃后重读仍按原流程处理；不会自动无限重试。

传输层每次调用显式指定config.env，同一原请求对象在本进程内绑定首次实际调用的环境，跨client重建也不跟随配置变化切到另一数据库空间；新请求可使用新环境。绑定使用WeakMap，不增加本地持久化或修改公共请求字段；复制请求对象、进程重启及不同账号会话的持久恢复不在此保证内。配置禁用时仍禁止调用，不能用已绑定环境绕过关闭开关。API与启动均要求cloudEnabled严格为true、环境为非空字符串、SDK方法存在；初始化失败保留cloudReady=false。
