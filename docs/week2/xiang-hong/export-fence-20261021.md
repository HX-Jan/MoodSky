# 导出创建与停用/来源变更的共同围栏

2026-10-21，本地候选修正；基线 `d208d01`。生产入口仍未引用导出工厂，没有部署、真实数据库操作或文件领取。

## 证据与问题

本轮首阶段已把来源读取和建任务放进同一事务，避免两次独立事务和旧重试闭包。进一步核对[腾讯云官方事务说明](https://cloud.tencent.com/document/product/876/48442)及[CloudBase 事务机制](https://docs.cloudbase.net/en/database/transaction)：事务基于快照，读文档不使用修改文档相同的锁。因此推断，仅读取 active 账号再写另一个任务文档，不足以建立与账号停用/来源修改的共同写入冲突。

先扩充锁定 SDK 离线传输夹具，可显式选择按已写文档版本检测冲突。负对照证明该模型允许“先读账号 → 另一事务停用 → 只写任务”，并保留两边已提交的不同文档；它不会靠全库版本冲突把问题自动掩盖。旧导出服务在这个模型中实际留下了新 pending 任务，且来源变化后仍绑定旧版本。该结果是合成模型复现，未在 CloudBase 执行，不宣称发现了真实文件泄漏。

## 修正与兼容边界

新任务在同一事务内读取账号/来源/原任务，并更新账号已有 operationFence，再写任务。它与停用及其他遵守同一账号写入协议的模块形成共同冲突文档。SDK 重跑回调时重查 active 和来源；成功原请求重放只返回原元数据，不重建任务，也不重复推进围栏。

- 只增加一次新任务的账号元数据更新，不改变 journalRevision、exportEpoch、文件引用或来源内容；围栏与任务整体提交/回滚。
- **兼容取舍**：旧账号没有 operationFence 时，新建导出返回 NOT_IMPLEMENTED，不初始化或迁移字段；损坏/耗尽计数器拒绝创建。只读 gatherExportData 保持原接口及投影，纯围栏变化不会让其误判来源改变。
- 五类来源写入及停用必须共同遵守账号协议；来源适配器必须从传入事务读取真实版本。测试中的其他域0计数不是实际接入证据。
- 真实 CloudBase 可能在文档写阶段而非提交阶段报告冲突，锁定 SDK 仍可能把它转为 -501001。保持未知错误和原请求重试，不把所有数字错误转为 CONFLICT 或自动增加业务重试。历史 H03 五项失败仍未关闭。

没有改公开 action、共享类型、数据库清单或正式默认入口。该候选前置条件需 Xiang Yu/Jiawei 共同确认；拥有者本地集成不代替其独立验收。
