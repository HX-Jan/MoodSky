## 设计依据和适配范围

`cloudbase-candidate.js` 实现 [后端事务存储接口](../../docs/local-journal-backend.md)，目标是项目锁定的 `wx-server-sdk 4.0.2` 和 `@cloudbase/database 1.5.1`。构造参数必须是服务器创建的 `cloud.database({throwOnNotFound:false})`；不能换成原始 Node SDK 而沿用 `{data:...}` 参数。

[CloudBase 官方事务说明](https://docs.cloudbase.net/database/transaction)列出单事务最多 100 个操作、30 秒限制，且事务只支持 doc 定位，不支持 where。候选因此使用确定文档 ID；90 天回顾做一次账号读取和 90 次日记录读取，共 91 次数据读取，来自同一事务。没有使用默认查询条数或先后独立分页；真实环境的时延、费用和 30 秒限制尚未测量。

同时直接核对本项目锁定依赖的源码：wx SDK 的 `DocumentReference.get/set/update` 及 `Transaction` 包装、数据库 SDK 的 `transaction/index.js` 和实际使用的 `document.js`。离线测试经过这些真实序列化/包装代码，只替换最底层请求传输，额外封锁 HTTP/HTTPS 网络回退。文档说明不能替代锁定版本的实际验证。

## 待评审的数据布局

这是不同于现有字段初稿的方案，尚未改动 `database/collections.json` 或成员数据字典：

- accounts 增加 `journalLayout:'deterministic-days-v1'` 和非负安全整数 journalRevision、operationFence、exportEpoch。缺少布局标记返回 `NOT_IMPLEMENTED`；字段损坏失败，不把随机 ID 旧记录误判为空，也不自动设置标记或迁移。
- journals 的 `_id` 为 SHA-256(JSON 编码的命名空间、内部账号、日期)前 32 位十六进制。另存 `ownerId/date/layout` 并复核，发现错配就失败。哈希截断不能数学上排除碰撞，校验避免错读其他归属。
- 业务记录 ID 使用独立 `entryId`；删除后日期文档仅保留布局、归属、日期、状态和版本，正文、标签、天气及时间戳全部通过整文档替换移除。重建沿用日期文档键，但生成新的业务 ID 并延续版本。
- request_receipts 按账号/action/requestId 定位，保存带密钥 HMAC 摘要、规范化和密钥版本、调用/到期时刻及业务结果，不存正文。到期最小键占用标记仍拒绝重放。原字段缺省与显式空值不同；保留期和密钥管理仍待确认。
- 当前候选写 UTC ISO 字符串；现有字典拟使用数据库 Date/serverDate。二者需要明确迁移和转换，不能静默混用。

所有读取和写入事务都重新读取同一个 accounts 文档并检查 active、布局和源版本。实际写入同时更新该账号源版本；账号状态不能只依赖路由较早的检查。跨服务停用/清理必须使用兼容的账号文档和事务规则，实际竞争仍待云端验证。

## 恢复前检查候选

`recovery-plan.js` 接收声明为独立、完整且水位线覆盖备份时刻至恢复截止时刻的删除账本，以及同账号的确定 ID 布局备份。来源计数器必须齐全；缺失、越界或损坏均返回 blocked，不根据备份内回滚的标记猜测安全性。

它只生成无正文计划：把被较新删除代际覆盖的旧行替换为墓碑，补回缺失日期的版本墓碑，保留合法新 entryId/较新版本，拒绝删除后复用旧 ID 或携带正文的删除态。计划同时保留来源版本下限和独立账号停用状态，要求未来执行器重新使旧导出失效。日期墓碑重放幂等；没有实际执行数据库更新或文件删除。

无论返回 plan 或 blocked，`mayOpenPrivateServices` 始终为 false。布尔声明不是对账本来源的认证；真实独立备份、完整性证明、原子重放、其他领域/缓存/导出修复和独立验收仍未完成。8 项离线合成检查只说明计划逻辑，不说明平台备份恢复能力已验证；同一删除代际对应多个业务 ID 等矛盾输入会被拒绝。

